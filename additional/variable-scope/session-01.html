Additional Lesson A2

Variable Scope (Simplified)

One idea only: where you write a variable decides where you may use its name. Think of rooms in a house — a book left in the kitchen is not on the bedroom shelf.

⏱ ~2 Hours Integrated 📋 Session A2.1 🟢 Short & simple

Learning Outcomes – After this session you will be able to:

  • Say what “scope” means in one sentence
  • Point to fields, parameters, and local variables in a short class
  • Spot a compile error when a name is used outside its room
  • Use this.name when a parameter has the same name as a field

1. Scope in One Sentence

Definition — Scope

Scope is the part of the program where a variable’s name is known and can be used. Outside that part, the name does not exist (the compiler will complain).

House analogy:

  • Field = furniture that belongs to the whole house (the object). Every room (method) can use it.
  • Local variable = a shopping bag you carry into one room only. When you leave the room, the bag is gone.
  • Parameter = a gift handed to you at the door of a method. You may use it only inside that method.
Figure A2.1 — Fields belong to the class; parameters and locals belong to one method only.

2. Three Places to Declare a Variable

2.1 Field (instance variable)

Declared inside the class, but outside any method. Lives as long as the object lives.

public class Student {
    private String name;   // FIELD — whole class can use this (via methods)
    private int marks;     // FIELD
}

2.2 Parameter

Declared in the method’s parentheses. Exists only while that method runs.

public void setMarks(int marks) {   // "marks" is a PARAMETER
    // use marks here only
}

2.3 Local variable

Declared inside a method body (or inside { }). Exists from that line until the closing }.

public void printGrade() {
    int total = marks;        // LOCAL
    String grade = "Pass";    // LOCAL
    System.out.println(grade + " " + total);
}   // total and grade disappear here
🧠 Beginner’s Logic Breakdown
  1. Ask: “Where did I write the name?” → class body, method ( … ), or inside { }.
  2. Fields = object memory. Locals/parameters = temporary notes for one method call.
  3. If the compiler says “cannot find symbol”, you are probably outside the variable’s room.

3. A Mistake You Must Recognise

public class Demo {
    public void show() {
        int x = 10;
        System.out.println(x);   // OK
    }

    public void other() {
        System.out.println(x);   // ERROR — x is not in this room
    }
}
Note

x was born inside show(). Method other() is a different room. Fix: make x a field if both methods need it, or pass it as a parameter.

3.1 Block scope (if / for)

A variable declared inside if, for, or any { } is local to that block only.

if (marks >= 50) {
    String msg = "Pass";
    System.out.println(msg);   // OK
}
// System.out.println(msg);    // ERROR — msg ended with the if-block

4. Same Name Twice? Use this

Sometimes a parameter has the same name as a field. Inside the method, the parameter wins (it “hides” the field). Use this to mean the field.

public class Book {
    private String title;           // FIELD

    public void setTitle(String title) {   // PARAMETER — same name
        this.title = title;         // this.title = field, title = parameter
    }
}
Tip — Remember

this = “this object.” So this.title means “the field belonging to this object,” not the parameter.

NameMeaning inside setTitle
titleThe parameter (the value you passed in)
this.titleThe field on the Book object

5. Tiny Worked Example

public class Counter {
    private int count;                 // field — shared by all methods of this object

    public void add(int value) {       // value = parameter
        int next = count + value;      // next = local
        count = next;
    }

    public int getCount() {
        return count;                  // uses field; cannot see "value" or "next"
    }
}
🔬 Lab Task A2.1 — Label the Names (30 min)
  1. Type the Counter class above into VS Code and run a small main that calls add(5) twice, then prints getCount().
  2. In your lab book, draw three boxes: Field / Parameter / Local. Write each name (count, value, next) in the correct box.
  3. Deliberately add System.out.println(next); inside getCount(). Read the compiler error. Fix it by removing that line.
🔬 Lab Task A2.2 — Fix the Scope Bug (30 min)
  1. Write a Student class with a private field name.
  2. Write setName(String name) that correctly stores the parameter into the field using this.name = name;.
  3. Write greet() that prints "Hello, " + name.
  4. Challenge: inside greet(), declare a local String name = "Guest"; and print both the local and the field (this.name). Explain the two different values to a classmate.
Likely Exam Questions from Additional A2

  2. Difference between a field and a local variable. (4 marks)
  3. Why does using a local variable from another method cause a compile error? (3 marks)
  4. Explain why we write this.name = name; in a setter. (4 marks)

Session A2.1 Summary

  • Scope = where a name is visible.
  • Field → whole object. Parameter / local → one method (or one block).
  • Leaving the room destroys locals; fields stay with the object.
  • Same names? Inner wins; use this.field for the field.
