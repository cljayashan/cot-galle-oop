Classes & Objects – Fields and Methods

The core skill of the whole module: designing classes with fields and methods, creating independent objects, and driving them from a menu program. Examples: Vehicle, BankAccount — and the start of the Library System project.

⏱ 10 Hours Integrated 📋 Sessions 04 – 06 📚 Library Project Phase 1

Learning Outcomes – After this lesson you will be able to:

  • Define class, object, instantiation, field and method
  • Create multiple independent objects and explain per-object field copies
  • Write methods with parameters and return values, including guard clauses
  • Store objects in a List and process them with foreach
  • Build a menu-driven console application around a class

1. Class vs Object (Session 04)

Definitions

Class = blueprint describing fields + methods (no data memory itself). Object = a concrete instance created with new; each object owns its own copy of every field. Creating an object = instantiation.

class Vehicle
{
    public String Brand;      // FIELD – declared in the class, outside methods
    public int Speed;

    public void accelerate()  // METHOD – behaviour on this object's fields
    {
        Speed += 10;
    }
}

Vehicle car = new Vehicle();  // instantiation
car.Brand = "Toyota";         // dot operator: member belonging to car
car.accelerate();             // changes ONLY car.Speed, not any other vehicle
  • Noun/verb design: nouns → classes; what each must remember → fields; verbs → methods.
  • One class per .java file (Explorer → New File → ClassName.java).

2. Methods in Depth – BankAccount (Session 05)

Signature = access modifier + return type + name + parameters: public boolean withdraw(double amount).

public boolean withdraw(double amount)
{
    if (amount > Balance)        // guard clause = flowchart decision diamond
    {
        return false;            // refuse and tell the caller
    }
    Balance -= amount;
    return true;                 // success travels back to the calling line
}
  • Parameters copy values in; return sends one value out; void = nothing returned.
  • Use double for money in labs; String.format("%.2f", value) formats currency.
  • Design rule: fields change only through methods that enforce the business rules.

3. Library System Phase 1 (Session 06)

Book class (Title, Author, ISBN, isAvailable) with borrow/returnItem/printDetails, plus:

import java.util.ArrayList;
import java.util.List;

List<Book> catalog = new ArrayList<>();   // resizable, type-safe container
catalog.add(b1);

for (Book b : catalog)               // visit every object
{
    b.printDetails();
}

Book found = null;                         // null = "no object"; check before use!
  • Menu pattern: while (running) + if/else on the user's choice.
  • Search pattern: loop, remember the match, check for null afterwards.

Lesson 03 Summary

  • Class = blueprint; object = instance with its own field copies; new instantiates.
  • Method signature has four parts; parameters in, return value out, guard clauses protect state.
  • List<T> + enhanced-for manage many objects; null must be checked after searching.
  • Library System Phase 1 delivered: Book class + working menu program.
