Inheritance

Look at any real system: a Car, a Bus and a Motorbike share 90% of their behaviour. Copy-pasting that 90% into three classes is a maintenance nightmare. Inheritance lets one class receive everything from another and add only what's different — the family tree of code.

⏱ 3 Hours Integrated 📋 Session 14 of 23 🏛 Pillar 2 of 4

Learning Outcomes – After this session you will be able to:

  • Define inheritance and identify "is-a" relationships
  • Create derived classes with the extends keyword
  • Explain what a child class inherits and what it does not
  • Add child-specific fields and methods on top of inherited ones
  • Draw and read simple class hierarchy diagrams

1. The Problem: Sibling Classes Repeating Themselves

// WITHOUT inheritance — painful duplication:
class Car {
    private String brand;
    protected int speed;
    private int numberOfDoors;

    public String getBrand() { return brand; }
    public void setBrand(String brand) { this.brand = brand; }
    public int getSpeed() { return speed; }
    public int getNumberOfDoors() { return numberOfDoors; }
    public void setNumberOfDoors(int numberOfDoors) { this.numberOfDoors = numberOfDoors; }

    public void accelerate() { speed += 10; }          // identical
    public void brake() { speed = 0; }                 // identical
}

class Motorbike {
    private String brand;                              // copy-pasted!
    protected int speed;                                 // copy-pasted!
    private boolean hasSideCar;                        // bike-specific

    public String getBrand() { return brand; }
    public void setBrand(String brand) { this.brand = brand; }
    public int getSpeed() { return speed; }
    public boolean hasSideCar() { return hasSideCar; }
    public void setHasSideCar(boolean hasSideCar) { this.hasSideCar = hasSideCar; }

    public void accelerate() { speed += 10; }          // copy-pasted!
    public void brake() { speed = 0; }                 // copy-pasted!
}
// A bug in accelerate must now be fixed TWICE. Add a Bus? THREE times. This does not scale.
Definition — Inheritance

Inheritance is a mechanism where a class (the derived/child class) automatically receives all non-private members of another class (the base/parent class), and can add its own members on top. In Java, the extends keyword declares it: class Car extends Vehicle reads as "Car is a Vehicle".

The "is-a" Test

Use inheritance only where the sentence "X is a Y" sounds naturally true. A Car is a Vehicle ✓. A Student is a Person ✓. An Engine is a Car? ✗ — an engine is part of a car; that's composition (Lesson 09), not inheritance.

1.1 The Solution — One Parent, Many Children

// File: Vehicle.java — the BASE (parent) class holds everything common
package garage;

class Vehicle {
    private String brand;
    private int year;
    protected int speed;

    public String getBrand() { return brand; }
    public void setBrand(String brand) { this.brand = brand; }
    public int getYear() { return year; }
    public void setYear(int year) { this.year = year; }
    public int getSpeed() { return speed; }

    public void accelerate() {
        speed += 10;
        System.out.println(brand + " is now going " + speed + " km/h");
    }

    public void brake() {
        speed = 0;
        System.out.println(brand + " stopped.");
    }
}
// File: Car.java — "extends" means "Car inherits from Vehicle"
package garage;

class Car extends Vehicle {                     // Car IS A Vehicle
    // Car adds ONLY what makes a car special:
    private int numberOfDoors;

    public int getNumberOfDoors() { return numberOfDoors; }
    public void setNumberOfDoors(int numberOfDoors) { this.numberOfDoors = numberOfDoors; }

    public void openBoot() {
        System.out.println("The " + getBrand() + "'s boot is open.");   // brand is INHERITED
    }
}
// File: Motorbike.java
package garage;

class Motorbike extends Vehicle {
    private boolean hasSideCar;

    public boolean hasSideCar() { return hasSideCar; }
    public void setHasSideCar(boolean hasSideCar) { this.hasSideCar = hasSideCar; }

    public void doWheelie() {
        System.out.println("The " + getBrand() + " pops a wheelie! (Don't try this at home)");
    }
}
// In main — children can use inherited AND own members:
Car car = new Car();
car.setBrand("Toyota");          // inherited — works!
car.setNumberOfDoors(4);         // own field
car.accelerate();                // inherited method  -> "Toyota is now going 10 km/h"
car.openBoot();                  // own method

Motorbike bike = new Motorbike();
bike.setBrand("Bajaj");
bike.accelerate();               // the SAME inherited code — written once, used by all children
bike.doWheelie();

// car.doWheelie();              // COMPILER ERROR — wheelie belongs to Motorbike only
Figure 14.1 — A class hierarchy. The hollow arrow points from child to parent and reads "is a". Common code lives once, at the top.
🧠 Beginner's Logic Breakdown
  1. Read class Car extends Vehicle aloud: "Car is a Vehicle." Everything a Vehicle has, a Car automatically has — without writing it again.
  2. Inside openBoot() we used getBrand() even though Car never declared it — the field/getter arrived through inheritance, as if it were pasted in invisibly.
  3. Inheritance is one-directional: children get the parent's members; the parent knows nothing about its children. Vehicle cannot call doWheelie().
  4. What is NOT inherited: private members exist inside the child object but are inaccessible to the child's code (Session 15 fixes this with protected), and constructors are not inherited (also Session 15).

1.2 Rules of Java Inheritance

  • Single inheritance only: a class may have exactly one direct superclass (class A extends B, C with two classes is illegal in Java — use implements for interfaces).
  • Chains are allowed: ElectricCar extends Car extends Vehicle — ElectricCar inherits from both, transitively.
  • Everything ultimately inherits from Object: the built-in root class of all Java types — this is why every object has toString().

Session 14 Summary

  • class Child extends Parent — the child receives all non-private members automatically.
  • Use inheritance only for true "is-a" relationships; "part-of" is composition (Lesson 09).
  • Common code lives once in the base; children add only their specialities.
  • Java allows one direct superclass; chains are fine; everything roots at Object.
  • Fix a base-class bug once — every child is fixed instantly.
