Lesson 07 of 10 — The Second Pillar of OOP

Inheritance — Code Reuse Through Class Hierarchies

When Car, Bus and Motorbike share 90% of their behaviour, copy-pasting is a maintenance nightmare. Inheritance lets one class receive everything from another and add only what is different.

⏱ 10 Hours Integrated 📋 Sessions 14 – 16 🏛 Pillar 2 of 4

Learning Outcomes — After this lesson you will be able to:

  • Define inheritance and create derived classes with the extends keyword
  • Apply the "is-a" test and design class hierarchies
  • Use protected and super(...) constructor chaining
  • Refactor the Library System into a LibraryItem hierarchy (Phase 4)

Lesson 07 Summary

  • class Child extends Parent — child receives all non-private members.
  • Use inheritance only for true "is-a" relationships.
  • protected = family access; super(args) chains constructors upward.
  • LibraryItem base owns shared borrow logic; Book and Dvd add their own data.
