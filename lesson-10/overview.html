Association, Aggregation & Composition

Beyond inheritance ("is-a"), real systems connect objects through "uses-a", "has-a", and "part-of". The School project (Teacher, Classroom, Desk) puts every relationship type into one working console application.

⏱ 15 Hours Integrated 📅 Sessions 21 – 23 🏫 School System Project

Learning Outcomes – After this lesson you will be able to:

  • Define association, aggregation and composition with UML-style diagrams
  • Implement each relationship in Java and explain lifetime rules
  • Build a multi-class School system with Teacher–Classroom association
  • Model Classroom–Desk composition where desks are destroyed with the classroom

1. The Three Relationships (Session 21)

RelationshipPhraseLifetimeExample
Associationuses-a / knowsBoth independentTeacher → Classroom
Aggregationhas-a (detachable)Part outlives wholeClassroom ◇ Student
Compositionpart-of (owned)Part dies with wholeClassroom ◆ Desk

Key giveaway: where is the part object created? Outside and handed in → aggregation. Inside the whole's constructor → composition.

2. School Project Part 1 (Session 22)

  • Teacher uses Classroom — association with two-way linking via AssignTo.
  • Classroom has Students — aggregation; students transfer between rooms.
  • Business rules: one teacher per room, one room per student (guard clauses).

3. School Project Part 2 (Session 23)

  • Classroom composed of Desks — desks created in constructor; capacity = desk count.
  • School composes Classrooms — BuildClassroom creates rooms inside the school.
  • Final demo: enrol, transfer, fill rooms, print summary — module complete.

Lesson 10 Summary

  • Association = loose link; aggregation = shared parts; composition = owned parts that die with the whole.
  • Teacher uses Classroom; Classroom has Students; Classroom has Desks (composition — desks destroyed with classroom).
  • Encapsulation guards relationship boundaries — private collections, public Enroll/Build methods.
  • You have now used all four OOP pillars and all three relationship types in working Java systems.
