1. Anatomy of a Method

In Session 04 you called methods like car.accelerate() with no extra information. Real programs need methods that receive values and sometimes send answers back — exactly like a flowchart process box that reads inputs and produces an output.

Definition — Method

A method is a named block of code inside a class that performs a task. It may receive input values (parameters) and may send back a result (return value). A method is the OOP version of the "function" or "subroutine" you met in flowchart notation.

Figure 2.3 — The four parts of every method signature.

Think of a method as a vending machine: parameters are the coins and button press you put in; the return value is the drink that comes out; the machine's internal work is the method body — invisible to the caller.

2. The BankAccount Class — Methods That Protect Data

A bank account is the perfect example because its rules are familiar: you cannot withdraw more than you have, and you cannot deposit a negative amount. Notice how the methods enforce the rules — this previews encapsulation (Lesson 03).

Money and floating point

double uses binary floating-point and can give tiny rounding errors (e.g. 0.1 + 0.2 ≠ 0.3 exactly). Real banks often use BigDecimal. In this module we use double for simplicity and format with String.format("%.2f", value).

// File: BankAccount.java

    class BankAccount
    {
        // ---------- FIELDS ----------
        public String AccountNumber;
        public String OwnerName;
        public double Balance;        // double is THE type for money in Java

        // ---------- METHODS ----------

        // Takes input, returns nothing: changes the object's state safely
        public void deposit(double amount)
        {
            if (amount <= 0)                          // guard clause: reject bad input
            {
                System.out.println("deposit must be positive!");
                return;                               // 'return' alone exits a void method early
            }
            Balance = Balance + amount;               // can also be written: Balance += amount;
            System.out.println("deposited " + String.format("%.2f", amount) + ". New balance: " + String.format("%.2f", Balance));
        }

        // Takes input AND returns a result: true = success, false = refused
        public boolean withdraw(double amount)
        {
            if (amount <= 0)
            {
                System.out.println("withdrawal must be positive!");
                return false;
            }
            if (amount > Balance)                     // the golden rule of banking!
            {
                System.out.println("Insufficient funds. Balance is only " + String.format("%.2f", Balance));
                return false;
            }
            Balance -= amount;
            System.out.println("Withdrew " + String.format("%.2f", amount) + ". New balance: " + String.format("%.2f", Balance));
            return true;
        }

        // Takes input and returns a computed value without changing Balance
        public double calculateAnnualInterest(double ratePercent)
        {
            double interest = Balance * (double)ratePercent / 100;
            return interest;                          // hand the answer to the caller
        }

        public void printStatement()
        {
            System.out.println("--------------------------------");
            System.out.println("Account : " + AccountNumber);
            System.out.println("Owner   : " + OwnerName);
            System.out.println("Balance : " + String.format("%.2f", Balance));
            System.out.println("--------------------------------");
        }
    }

// File: Main.java

    public class Main
    {
        public static void main(String[] args)
        {
            BankAccount acc = new BankAccount();
            acc.AccountNumber = "ACC-1001";
            acc.OwnerName = "Nimali Perera";
            acc.Balance = 0;

            acc.deposit(5000);           // OK — 5000 copied into amount parameter
            acc.deposit(-50);            // rejected by the guard clause

            boolean ok = acc.withdraw(1200);        // ok becomes true
            boolean ok2 = acc.withdraw(99999);      // refused → ok2 is false
            System.out.println("Second withdrawal succeeded? " + ok2);

            // Use the returned value in a calculation
            double interest = acc.calculateAnnualInterest(4.5);
            System.out.println("Interest at 4.5% would be: " + String.format("%.2f", interest));

            acc.printStatement();
            // pause: new java.util.Scanner(System.in).nextLine();
        }
    }
🧠 Beginner's Logic Breakdown
  1. Parameter = a mailbox: when Main calls acc.deposit(5000), the value 5000 is copied into the parameter amount. Inside the method, amount behaves like a normal variable that arrived pre-filled.
  2. Guard clauses are your flowchart's DECISION diamonds: if (amount <= 0) ... return; is exactly the diamond "amount ≤ 0? → yes: reject / no: continue". Decisions you drew in flowcharts now protect real data.
  3. Return values travel back: return interest; sends the number back to the calling line, where it lands in double interest = .... Trace it with your finger: Main → method → back to Main.
  4. {Balance:C} formats a number as currency (e.g. Rs. depending on region settings). Just formatting — no maths involved.
  5. Why boolean for withdraw? The caller may need to know whether it worked — e.g. an ATM must only dispense cash if the withdrawal succeeded.
Key Point — Methods Guard the Data

Nobody should change Balance directly with arbitrary values. All changes go through deposit and withdraw, which check the rules first. In Lesson 03 we make this bulletproof by marking fields private so direct access becomes impossible.

Common Beginner Errors
  • Missing return on non-void methods: every path through withdraw must hit a return — compiler error if one branch forgets.
  • Using double for money: prefer BigDecimal in production; use double carefully in these labs.
  • Confusing parameter and argument: the parameter is in the method header (double amount); the argument is the value you pass at the call site (5000).
  • Expecting void to return: deposit changes state but gives nothing back — do not write double x = acc.deposit(100);

Step 2 — The Book Class (Phase 1 Style — Public Fields)

In Phase 1 we use public fields for simplicity. In Session 09 (Phase 2) we refactor to private fields and properties — the same Book, better protected.

// File: Book.java

    class Book
    {
        // ---------- FIELDS: what every book remembers ----------
        public String Title;
        public String Author;
        public String ISBN;
        public boolean isAvailable = true;   // new books start available

        // ---------- METHODS: what every book can do ----------

        public void borrow()
        {
            if (isAvailable == false)                 // guard: already borrowed?
            {
                System.out.println("Sorry, '" + title + "' is already borrowed.");
                return;                               // stop — rule was broken
            }
            isAvailable = false;                      // mark as taken
            System.out.println("You have borrowed '" + title + "'. Enjoy!");
        }

        public void returnBook()
        {
            if (isAvailable)                          // returning a book never borrowed?
            {
                System.out.println("'" + title + "' was not borrowed — nothing to return.");
                return;
            }
            isAvailable = true;
            System.out.println("'" + title + "' has been returned. Thank you!");
        }

        public void printDetails()
        {
            // Conditional operator: compact if/else that picks a value
            String status = isAvailable ? "Available" : "Borrowed";
            System.out.println(title + " by " + author + " | ISBN: " + isbn + " | " + status);
        }
    }
🧠 Beginner's Logic Breakdown
  1. isAvailable = true at the field: every new Book starts life available — sensible defaults save setup code in Main.
  2. Borrow's guard clause: flowchart thinking — diamond: "available? no → print sorry, stop; yes → mark borrowed, print success." The method makes an illegal state (borrowing twice) impossible.
  3. condition ? valueIfTrue : valueIfFalse chooses a value in one line. Longer equivalent: if (isAvailable) status = "Available"; else status = "Borrowed";

Step 3 — Many Books: List and Menu Loop

A library has hundreds of books — we cannot write book1, book2, book3… forever. Java gives us List<Book>: a resizable container that holds any number of Book objects.

import java.util.ArrayList;
import java.util.List;

import java.util.Scanner;

// File: Main.java
// needed for List<T>


    public class Main
    {
        public static void main(String[] args)
        {
        Scanner scanner = new Scanner(System.in);
            // A List that can hold ONLY Book objects (type-safe container)
            List<Book> catalog = new ArrayList<>();

            // Create books and add them to the catalog
            Book b1 = new Book();
            b1.setTitle("Clean Code");  b1.Author = "Robert C. Martin";  b1.ISBN = "978-0132350884";
            catalog.add(b1);

            Book b2 = new Book();
            b2.Title = "The Pragmatic Programmer";  b2.Author = "Hunt & Thomas";  b2.ISBN = "978-0201616224";
            catalog.add(b2);

            Book b3 = new Book();
            b3.Title = "Head First Java";  b3.Author = "Andrew Stellman";  b3.ISBN = "978-1491976708";
            catalog.add(b3);

            // ---------- THE MENU LOOP ----------
            boolean running = true;
            while (running)                            // repeat until user chooses Exit
            {
                System.out.println("\n===== COT LIBRARY =====");
                System.out.println("1. List all books");
                System.out.println("2. Borrow a book");
                System.out.println("3. Return a book");
                System.out.println("4. Exit");
                System.out.print("Choose: ");
                String choice = scanner.nextLine();

                if (choice == "1")
                {
                    for (Book b : catalog)        // visit every Book, one at a time
                    {
                        b.printDetails();
                    }
                }
                else if (choice == "2" || choice == "3")
                {
                    System.out.print("Enter the exact title: ");
                    String title = scanner.nextLine();

                    Book found = null;                 // null = "no object yet"
                    for (Book b : catalog)
                    {
                        if (b.setTitle(= title)
                        {
                            found = b;                 // remember which book matched
                        }
                    }

                    if (found == null)
                    {
                        System.out.println("No book with that title.");
                    }
                    else if (choice == "2")
                    {
                        found.borrow();
                    }
                    else
                    {
                        found.returnBook();
                    }
                }
                else if (choice == "4")
                {
                    running = false;                   // ends the while loop
                }
                else
                {
                    System.out.println("Please choose 1-4.");
                }
            }
            System.out.println("Goodbye!");
        }
    }
Figure 2.6 — Menu flowchart: while loop with decision diamonds — the same pattern you drew before writing code.
🧠 Beginner's Logic Breakdown
  1. List<Book> reads as "a List of Book". catalog.add(b1) puts an object in; for (Book b : catalog) takes each one out in turn.
  2. The menu is a loop + decisions — exactly the "repeat until user exits" pattern from flowcharts, with a diamond for each menu option.
  3. null means "no object here yet". We start search with found = null; if still null after the loop, no title matched. Checking before use prevents NullReferenceException.
  4. Trace one round: user picks 2, types "Clean Code" → loop matches b1 → found.borrow() → isAvailable true → marks false → back to menu.
