1. From Flowcharts to Code — The Same Thinking, a New Language

Until now you have solved problems using algorithms (numbered steps) and flowcharts (diagrams with boxes and arrows). A flowchart is not just a drawing — it is a precise description of what a computer should do. When you write Java code, you are writing that same description in a language the computer can execute directly.

Consider a simple problem: display a welcome message on screen. As a flowchart:

Figure 1.1 — The simplest possible flowchart: START → OUTPUT → END. Every Java program follows this same top-to-bottom flow.

Now look at a slightly richer example — the rectangle area problem you already know:

Key Point

Coding is not a different way of thinking — it is the same logical thinking you already practise with flowcharts, expressed in a stricter language. The computer cannot guess what you mean; every step must be written precisely, in order, with correct spelling and punctuation.

Logic First, Syntax Second

Always draw or write your algorithm before touching the keyboard. If you cannot explain the steps on paper, you cannot write the code. The syntax (semicolons, braces, capital letters) is learnable — the logic is what makes you a programmer.

2. Meet Your Toolbox: VS Code

To write and run Java programs we need an IDE (Integrated Development Environment) — one application that combines a code editor, a compiler, and a debugger. Our IDE for this module is Visual Studio Code (VS Code), which is free. Only VS Code is allowed in this module.

Definition — IDE

An Integrated Development Environment (IDE) is a software application that provides everything a programmer needs in one place: a smart text editor (with colour-coding and auto-complete), a compiler (translates your human-readable code into a runnable program), and a debugger (helps you find and fix mistakes step by step).

3. Your First Java Program — Hello World

Replace the contents of Hello.java with this and study every line — the comments (text after //) explain each part. Do not worry if some words look strange; we unpack them fully in Session 02.

// This is a comment. The computer ignores everything after "//".
// Comments are notes for humans reading the code.

public class Hello                      // A class - a container that holds our program's code
{                                       // Class name must match the file name: Hello.java
    public static void main(String[] args) // main = the ENTRY POINT. The program starts here
    {
        // System.out.println prints one line of text on the screen
        System.out.println("Hello, College of Technology Galle!");
    }                                   // End of the main method
}                                       // End of the Hello class
🧠 Beginner's Logic Breakdown

Map this code to the flowchart thinking you already know:

  1. START = the program begins at the first line inside main. The JVM always looks for a method called main to know where to start — like the START oval in your flowchart.
  2. OUTPUT box = System.out.println("..."). Whatever is inside the quotes gets displayed. This is exactly your flowchart's OUTPUT parallelogram.
  3. END = when the program reaches the closing brace } of main, it stops. When main ends, the program stops — in VS Code the Terminal keeps the output visible.
  4. The other lines (import, package, class) are the packaging — like the envelope around a letter. We study them properly in Session 02. For now: your instructions go inside main.

To run the program click Run above main, or press Ctrl + F5 (Run without debugging). Output appears in the Terminal. Congratulations — you are officially a programmer!

3.1 Optional — Run from the Terminal in VS Code (javac / java)

VS Code is our main tool. You can also compile and run a single Java file from the integrated Terminal (View → Terminal). This is useful for a quick check with the JDK tools.

// Save this as Hello.java in any folder
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello from the command line!");
    }
}
javac Hello.java && java Hello
CLI vs VS Code Run
  • VS Code — Explorer, Editor, Terminal, PROBLEMS panel, debugger, code completion. Use this for all module labs.
  • javac Hello.java && java Hello — optional one-file experiments from the VS Code Terminal (requires the JDK on PATH). Same language; different launcher.
  • If javac is not recognised, install the JDK from adoptium.net and ensure it is on PATH, then reopen the Terminal.
Common Beginner Errors
  • Missing semicolon ; — every Java statement ends with ;. Forgetting it gives the error "; expected".
  • Wrong quotes — text must be inside straight double quotes "like this".
  • Case sensitivity — Java is case-sensitive. It must be System.out.println — capital S on System.
  • Unmatched braces { } — every opening { needs a closing }. VS Code highlights the matching pair when you click one.

Anatomy of a Java Program – Keywords, Structure & jshell

1. The Full Program Skeleton — Revisiting Session 01

In Session 01 you ran a program without fully understanding its "packaging". Now let's open up that packaging layer by layer. Here is the complete skeleton again — this time, every part labelled:

// --------------- LINE 1: A COMMENT ---------------
// Comments start with // and are ignored by the compiler.

// Optional: import libraries you need (e.g. Scanner for keyboard input)
// import java.util.Scanner;

package myfirstprogram;          // -- PACKAGE: a labelled container for our code (optional for first labs)

public class Hello               // -- CLASS: a container that holds related code (file: Hello.java)
{                                // -- OPENING BRACE: starts the class block
    public static void main(String[] args)  // -- main: the entry point
    {                            // -- OPENING BRACE: starts the main method block
        System.out.println("Hello!");  // -- SEMICOLON: every statement ends with ;
    }                            // -- CLOSING BRACE: ends main
}                                // -- CLOSING BRACE: ends class Hello
Figure 2.1 — Package → Class → main method → your statements. Every Java console program has this skeleton.

2. The Building Blocks Explained

2.1 Comments — Notes for Humans

A comment is text the compiler completely ignores. It exists only to help you (and other programmers) understand the code.

StyleSyntaxWhen to Use
Single-line// anything after these two slashesShort explanations above a line or block
Multi-line/* text spanning several lines */Longer explanations (use sparingly)

2.2 Semicolons — Full Stops for Statements

Every Java statement (one complete instruction) must end with a semicolon ;. Think of it as a full stop at the end of a sentence. Without it, the compiler does not know where one instruction ends and the next begins.

System.out.println("Hello");   // → correct — ends with ;
System.out.println("Hello")    // → error — '; expected

2.3 Braces — Defining Blocks of Code

Curly braces { } group related lines together into a block. Every opening { must have a matching closing }. VS Code highlights matching pairs when you click on one brace — use this feature constantly.

Indentation (the spaces before each line) is not required by Java but makes blocks readable. Press Shift + Alt + F (Format Document) to auto-format your code at any time.

2.4 import — Importing Libraries

The line import java.util.Scanner; at the top means: "I want to use the Scanner class without typing java.util.Scanner every time." For keyboard input you write import java.util.Scanner; so you can use Scanner without the full package path. System.out.println needs no import — System is always available. The JDK also gives you Math, Integer, and many other tools.

2.5 package — The Filing Cabinet

A package is a named container that groups related classes together and prevents name collisions. Two different projects can both have a class called Program, and as long as they are in different packages there is no confusion — just like two students named "Kasun" in different classes are identified by their class name.

2.6 class — The Code Container

A class is a container that holds related code. In Java, all code must live inside a class — you cannot write loose instructions floating on their own. For Lesson 01, our class is simply called Program and holds our main method. Later lessons introduce classes that model real things (students, books, bank accounts); for now, treat class as the required packaging around your instructions.

2.7 The main Method — The Entry Point

When you press Ctrl + F5 (or click Run above main), the JVM looks for exactly one method named main and starts executing from its first line. Let's decode its signature:

PartMeaning (simple version)
static"Belongs to the class itself." For now, always write static on main.
void"This method gives nothing back when it finishes." (Methods that return a value use a type name here instead — Session 07.)
mainThe special name JDK searches for. lowercase main matters!
(String[] args)A box for extra text the operating system can pass in. We will not use it in this lesson, but it must be written.
🧠 Beginner's Logic Breakdown
  1. Think of an envelope: package (optional) is the outer label, class is the letter inside, and main is where your actual message (the instructions) is written.
  2. Only Main runs automatically. Everything else is just structure. Your job as a beginner: put your instructions inside main, between its { and }.
  3. Order of execution: lines inside main run top to bottom, exactly like following arrows in a flowchart.

3. Java Keywords — Words You Will Meet

Java has about 100 keywords — words reserved by the language with special meaning. You cannot use them as variable names. The table below lists the most important ones you will encounter in the first few weeks. Do not memorise them all today — just recognise them when they appear.

KeywordWhat It Means (beginner level)Example Context
classDeclares a container for codeclass Program { }
staticBelongs to the class, not an instancepublic static void main(...)
voidThis method returns nothingvoid Main(...)
intA whole number (no decimals)int age = 25;
doubleA decimal numberdouble price = 19.99;

ifMake a decision — do something only when a condition is trueif (age >= 18) { ... }

Keywords vs. Identifiers

Keywords (like int, class) are reserved — you cannot rename them. Identifiers are names you choose: variable names (age), project names (MyFirstProgram), method names (CalculateArea). Choose identifiers that describe what they hold: studentName is better than x.

Case Sensitivity

Java is case-sensitive. System, system, and SYSTEM are three different identifiers. Keywords like class and Class are also different — only the lowercase version is valid.

4. Instant Experiments with jshell

Creating a whole project just to test one line of code is slow. The JDK includes a wonderful tool for instant experiments: jshell. You type one line, press Enter, and see the result immediately — no project, no main method, no compiling. In this module we run jshell from the VS Code Terminal.

  1. In VS Code open the Terminal: View → Terminal (or Ctrl + `).
  2. Type jshell and press Enter. A jshell> prompt appears.
  3. Type 2 + 3 and press Enter — it replies 5.
  4. Type int x = 10; and press Enter. Now type just x (no semicolon) and press Enter — it replies 10. The variable is alive in the session's memory!
  5. Try x * 2 + 1 → it instantly shows 21.
  6. Try "Hello" + " World" → it shows "Hello World". The + joins strings together.
  7. Try System.out.println("Test from jshell!"); — output appears in the jshell session.
  8. Type /exit when you are finished.
Why This Matters

jshell is your sandbox. Whenever you are unsure what a line of code does — test it here in five seconds instead of guessing. We will use it throughout the module to explore new concepts before writing full programs.
