1. Anatomy of a Method

In Session 04 you called methods like car.accelerate() with no extra information. Real programs need methods that receive values and sometimes send answers back — exactly like a flowchart process box that reads inputs and produces an output.

Definition — Method

A method is a named block of code inside a class that performs a task. It may receive input values (parameters) and may send back a result (return value). A method is the OOP version of the "function" or "subroutine" you met in flowchart notation.

Figure 2.3 — The four parts of every method signature.

Think of a method as a vending machine: parameters are the coins and button press you put in; the return value is the drink that comes out; the machine's internal work is the method body — invisible to the caller.

2. The BankAccount Class — Methods That Protect Data

A bank account is the perfect example because its rules are familiar: you cannot withdraw more than you have, and you cannot deposit a negative amount. Notice how the methods enforce the rules — this previews encapsulation (Lesson 03).

Money and floating point

double uses binary floating-point and can give tiny rounding errors (e.g. 0.1 + 0.2 ≠ 0.3 exactly). Real banks often use BigDecimal. In this module we use double for simplicity and format with String.format("%.2f", value).

// File: BankAccount.java

    class BankAccount
    {
        // ---------- FIELDS ----------
        public String AccountNumber;
        public String OwnerName;
        public double Balance;        // double is THE type for money in Java

        // ---------- METHODS ----------

        // Takes input, returns nothing: changes the object's state safely
        public void deposit(double amount)
        {
            if (amount <= 0)                          // guard clause: reject bad input
            {
                System.out.println("deposit must be positive!");
                return;                               // 'return' alone exits a void method early
            }
            Balance = Balance + amount;               // can also be written: Balance += amount;
            System.out.println("deposited " + String.format("%.2f", amount) + ". New balance: " + String.format("%.2f", Balance));
        }

        // Takes input AND returns a result: true = success, false = refused
        public boolean withdraw(double amount)
        {
            if (amount <= 0)
            {
                System.out.println("withdrawal must be positive!");
                return false;
            }
            if (amount > Balance)                     // the golden rule of banking!
            {
                System.out.println("Insufficient funds. Balance is only " + String.format("%.2f", Balance));
                return false;
            }
            Balance -= amount;
            System.out.println("Withdrew " + String.format("%.2f", amount) + ". New balance: " + String.format("%.2f", Balance));
            return true;
        }

        // Takes input and returns a computed value without changing Balance
        public double calculateAnnualInterest(double ratePercent)
        {
            double interest = Balance * (double)ratePercent / 100;
            return interest;                          // hand the answer to the caller
        }

        public void printStatement()
        {
            System.out.println("--------------------------------");
            System.out.println("Account : " + AccountNumber);
            System.out.println("Owner   : " + OwnerName);
            System.out.println("Balance : " + String.format("%.2f", Balance));
            System.out.println("--------------------------------");
        }
    }

// File: Main.java

    public class Main
    {
        public static void main(String[] args)
        {
            BankAccount acc = new BankAccount();
            acc.AccountNumber = "ACC-1001";
            acc.OwnerName = "Nimali Perera";
            acc.Balance = 0;

            acc.deposit(5000);           // OK — 5000 copied into amount parameter
            acc.deposit(-50);            // rejected by the guard clause

            boolean ok = acc.withdraw(1200);        // ok becomes true
            boolean ok2 = acc.withdraw(99999);      // refused → ok2 is false
            System.out.println("Second withdrawal succeeded? " + ok2);

            // Use the returned value in a calculation
            double interest = acc.calculateAnnualInterest(4.5);
            System.out.println("Interest at 4.5% would be: " + String.format("%.2f", interest));

            acc.printStatement();
            // pause: new java.util.Scanner(System.in).nextLine();
        }
    }
🧠 Beginner's Logic Breakdown
  1. Parameter = a mailbox: when Main calls acc.deposit(5000), the value 5000 is copied into the parameter amount. Inside the method, amount behaves like a normal variable that arrived pre-filled.
  2. Guard clauses are your flowchart's DECISION diamonds: if (amount <= 0) ... return; is exactly the diamond "amount ≤ 0? → yes: reject / no: continue". Decisions you drew in flowcharts now protect real data.
  3. Return values travel back: return interest; sends the number back to the calling line, where it lands in double interest = .... Trace it with your finger: Main → method → back to Main.
  4. {Balance:C} formats a number as currency (e.g. Rs. depending on region settings). Just formatting — no maths involved.
  5. Why boolean for withdraw? The caller may need to know whether it worked — e.g. an ATM must only dispense cash if the withdrawal succeeded.
Key Point — Methods Guard the Data

Nobody should change Balance directly with arbitrary values. All changes go through deposit and withdraw, which check the rules first. In Lesson 03 we make this bulletproof by marking fields private so direct access becomes impossible.

Common Beginner Errors
  • Missing return on non-void methods: every path through withdraw must hit a return — compiler error if one branch forgets.
  • Using double for money: prefer BigDecimal in production; use double carefully in these labs.
  • Confusing parameter and argument: the parameter is in the method header (double amount); the argument is the value you pass at the call site (5000).
  • Expecting void to return: deposit changes state but gives nothing back — do not write double x = acc.deposit(100);

  • Parameters carry values into a method; return carries one value back out.

Lesson 05 of 10 — Constructors & Overloading

Constructors & Overloading

In Phase 2 of the Library System, creating a Book took five separate lines — and it was easy to forget the ISBN. Constructors fix that: every object is born complete and valid in a single new expression. This lesson teaches how to write default and parameterized constructors, when they run, and how the this keyword resolves name clashes.

⏳ 10 Hours Integrated 📚 Sessions 10 – 12 📕 Library Project Phase 3

1. The Problem — Half-Built Objects

After encapsulation (Lesson 03), your Library Book had getters and setters. Creation still looked fragile:

// Phase 2 style — five steps, easy to forget one:
Book b = new Book();
b.setTitle("Clean Code");
b.setAuthor("Robert C. Martin");
b.setIsbn("978-0132350884");
b.setYearPublished(2008);
catalog.add(b);   // what if setIsbn was skipped? A book with no ISBN enters the catalog.

The object existed in an invalid state between line 1 and line 4. Nothing in the language forced us to finish the job. Constructors solve this: an object cannot be created without its essential data.

Definition — Constructor

A constructor is a special method that runs automatically, exactly once, at the moment an object is created with new. Its job is to put the new object into a valid starting state. It has the same name as the class and no return type — not even void.

2. Default vs Parameterized Constructors

2.1 Parameterized Constructor — Forces Complete Objects

class Book
{
    private String title;
    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }
    private String author;
    public String getAuthor() { return author; }
    public void setAuthor(String author) { this.author = author; }
    private String isbn;
    public String getIsbn() { return isbn; }
    // no public setter — write only inside this class
    private int yearPublished;
    public int getYearPublished() { return yearPublished; }
    public void setYearPublished(int yearPublished) { this.yearPublished = yearPublished; }
        private boolean isAvailable = true;
    public boolean isAvailable() { return isAvailable; }
    private void setAvailable(boolean isAvailable) { this.isAvailable = isAvailable; }

    // PARAMETERIZED constructor — requires title, author, isbn, year
    public Book(String title, String author, String isbn, int yearPublished)
    {
        this.title = title;
        this.author = author;
        this.isbn = isbn;              // constructor is inside the class — private set is allowed
        this.yearPublished = yearPublished;
        isAvailable = true;
    }
}

// One line — complete and valid by definition:
Book b = new Book("Clean Code", "Robert C. Martin", "978-0132350884", 2008);

Book broken = new Book();   // COMPILER ERROR — no parameterless constructor exists

2.2 Default Constructor — Sensible Empty Start

A default constructor takes no parameters. Java provides one automatically for every class — but only until you write any constructor yourself.

class Vehicle
{
    private String brand;
    public String getBrand() { return brand; }
    public void setBrand(String brand) { this.brand = brand; }
    private int speed;
    public int getSpeed() { return speed; }
    // no public setter — write only inside this class

    // DEFAULT (parameterless) constructor
    public Vehicle()
    {
        this.brand = "Unknown";
        this.speed = 0;
    }

    // PARAMETERIZED constructor — both can coexist (different parameter lists)
    public Vehicle(String brand)
    {
        this.brand = brand;
        this.speed = 0;
    }
}

Vehicle v1 = new Vehicle();           // uses default — brand = "Unknown"
Vehicle v2 = new Vehicle("Toyota");     // uses parameterized — brand = "Toyota"
Key Point — The Disappearing Default Constructor

If you define any constructor (even a parameterized one), Java stops generating the free empty constructor. new Book() then fails unless you explicitly write public Book() { }. This is deliberate: it prevents accidental half-built objects.

3. When Constructors Run & the No-Return-Type Rule

Figure 10.1 — Object birth timeline: new triggers memory allocation, then the constructor initialises the object, then the reference is handed back.

When does the constructor run? The instant the new expression executes — after memory is allocated but before your code can use the variable. You never write b.Book(...); the runtime calls it for you.

3.1 Constructor vs Ordinary Method

Figure 10.2 — Constructor vs method: the no-return-type rule is the classic exam trap. public void Book(...) is an ordinary method that never runs on new.

4. The this Keyword — Resolving Name Clashes

When a constructor parameter has the same name as a field, Java picks the closest match — the parameter. Use this to mean "the current object being constructed".

class Student
{
    private String name;
    private int age;
    private String indexNumber;

    public Student(String name, int age, String indexNumber)
    {
        this.name = name;               // this.name = FIELD;  name = PARAMETER
        this.age = age;
        this.indexNumber = indexNumber;
        // Without 'this.' the line  name = name  would assign the parameter to itself!
    }

    public void printReport()
    {
        System.out.println(indexNumber + ": " + name + ", age " + age);
    }
}

Student s = new Student("Kasun Perera", 20, "CTG/2024/001");
s.printReport();   // CTG/2024/001: Kasun Perera, age 20

The same pattern applies when parameters match property names in simple getter/setter pair style classes — though many developers prefer distinct names (title parameter, Title property) to avoid the clash entirely.

🧠 Beginner's Logic Breakdown
  1. Think of birth registration: the constructor is the clerk who fills in the newborn's identity card the moment they exist. No identity card, no valid citizen — no valid object.
  2. Arguments flow like any method: new Student("Kasun", 20, "CTG/2024/001") passes three values into three parameters, which are copied into the object's fields.
  3. The this disambiguator: inside the constructor body, bare name means the parameter. this.name explicitly targets the field belonging to the object being built.
  4. Read-only properties: a constructor can set public getter / no public setter or getter only (no setter) properties because it runs inside the class — external code still cannot change ISBN after creation.

Session 10 Summary

  • Constructor = special method; same name as class; no return type; runs once automatically at new.
  • Parameterized constructors force complete objects; default constructors provide sensible starting values.
  • Writing any constructor removes Java's free parameterless constructor unless you add one explicitly.
  • this.field resolves parameter/field name clashes during construction.
  • Constructors may initialise read-only and private-set properties — external code cannot undo that work.
