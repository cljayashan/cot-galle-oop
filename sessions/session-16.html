1. New Requirements from the Client

The Client's Request — Phase 4

"Our library also lends DVDs (title, director, duration — borrowable for 3 days). Borrowing and returning work the same way as books. Please don't make us maintain two copies of the same borrowing code!"

The client literally asked for inheritance. Both item types share: a title, availability, borrow/return logic. Each adds its own extras. Design:

Figure 16.1 — The Phase 4 hierarchy. Borrowing logic lives once in LibraryItem; Book and Dvd add their specific data.

2. Step-by-Step Build

Step 1 — Extract the Base Class

// File: LibraryItem.java  (NEW)
package librarysystem;

class LibraryItem {
    private String title;
    private boolean isAvailable = true;
    protected int loanDays = 14;   // children may adjust; outsiders use getter only

    public String getTitle() { return title; }
    public boolean isAvailable() { return isAvailable; }
    public int getLoanDays() { return loanDays; }

    public LibraryItem(String title) {
        this.title = title;
    }

    public boolean borrow() {
        if (!isAvailable) {
            System.out.println("Sorry, '" + title + "' is already borrowed.");
            return false;
        }
        isAvailable = false;
        System.out.println("Borrowed '" + title + "' — return within " + loanDays + " days.");
        return true;
    }

    public void returnItem() {
        if (isAvailable) {
            System.out.println("'" + title + "' was not borrowed.");
            return;
        }
        isAvailable = true;
        System.out.println("'" + title + "' returned. Thank you!");
    }

    public void printDetails() {
        String status = isAvailable ? "Available" : "Borrowed";
        System.out.println(title + " | loan " + loanDays + " days | " + status);
    }
}

Step 2 — Book Becomes a Child

// File: Book.java  (Phase 4 — now derived)
package librarysystem;

class Book extends LibraryItem {
    private String author;
    private String isbn;
    private int yearPublished;

    public String getAuthor() { return author; }
    public String getIsbn() { return isbn; }
    public int getYearPublished() { return yearPublished; }

    public Book(String title, String author, String isbn, int year) {
        super(title);                       // title travels up to LibraryItem
        this.author = author;
        this.isbn = isbn;
        this.yearPublished = year;
        // loanDays stays at the default 14 for books
    }
    // borrow, returnItem: DELETED here — inherited from LibraryItem. Less code than Phase 3!
}

Step 3 — Add the Dvd Sibling

// File: Dvd.java
package librarysystem;

class Dvd extends LibraryItem {
    private String director;
    private int durationMinutes;

    public String getDirector() { return director; }
    public int getDurationMinutes() { return durationMinutes; }

    public Dvd(String title, String director, int durationMinutes) {
        super(title);
        this.director = director;
        this.durationMinutes = durationMinutes;
        this.loanDays = 3;             // protected field lets the child change its own rule
    }
}
Figure 16.2 — Refactor direction: pull shared members up into LibraryItem, trim Book, add Dvd as a sibling.
🧠 Beginner's Logic Breakdown
  1. Refactor direction: we pulled up the members every item shares (Title, IsAvailable, Borrow, Return) into LibraryItem, then trimmed Book down to only its unique parts.
  2. protected setLoanDays(...) / getLoanDays(): the perfect protected use case — each child adjusts its own loan rule in its constructor, but no outsider can tamper.
  3. super(title) in every child ships the title up to the LibraryItem constructor — construction runs top-down: LibraryItem part first, then the child's extras.
  4. Spot the remaining wart: printDetails() shows only the base data — a Dvd prints no director. Session 18 fixes this with @Override (methods overridable by default) and a single polymorphic catalog.
