1. Methods — Reusable Steps in Your Program

So far every line of logic lived inside main. As programs grow, that becomes hard to read — like writing an entire recipe as one long paragraph with no numbered steps. A method is a named block of code that performs one job. You write it once, then call it whenever you need that job done.

Definition — Method (Procedural View)

A method is a named sequence of statements grouped together. Methods accept parameters (input data), may return a result, and can be called from main or from other methods. In this session methods are plain reusable steps — not object behaviour. OOP classes come in Lesson 02.

1.1 void Methods — Do Something, Return Nothing

A void method performs an action (print a message, display a menu) but does not send a value back to the caller.

public class MethodBasics
{
    public static void main(String[] args)
    {
        // CALL the method — execution jumps to displayWelcome, runs it, then returns here
        displayWelcome();

        int a = 10, b = 20;
        printSum(a, b);    // pass 10 and 20 as parameters
    }

    // METHOD DEFINITION — must be inside the class, alongside main
    static void displayWelcome()
    {
        System.out.println("=== Welcome to COT Galle ===");
        System.out.println("Basic Java Programming - Lesson 01");
    }

    // void method WITH parameters — receives two ints, prints their sum
    static void printSum(int x, int y)
    {
        int total = x + y;
        System.out.println(x + " + " + y + " = " + total);
    }
}

1.2 Return Types — Send a Value Back

Replace void with a type name (int, double, String, boolean) when the method computes a result the caller needs. Use return to send that value back.

// Returns an int — the caller can store or use the result
static int add(int x, int y)
{
    return x + y;    // sends the value back to whoever called add
}

// Usage inside main:
int result = add(5, 3);           // result is 8
System.out.println(add(10, 20));  // prints 30 directly

🧠 Beginner's Logic Breakdown — Methods
  1. Define once, call many times: write calculateArea once; call it for ten different rectangles without copying the formula.
  2. Parameters = flowchart inputs to a sub-process: the method receives values it needs; it does not have to read from the keyboard itself (though it can).
  3. return = OUTPUT from a sub-process: instead of printing inside the method, return the value and let main decide what to do with it — more flexible design.
  4. static for now: we stay inside one Program class. Lesson 02 introduces separate classes where methods belong to objects.

2. Capstone — Rectangle Flowchart to Procedural Java

This capstone brings together everything from Lesson 01: input, decisions, loops (if needed), and now methods. We solve the classic rectangle problem — but organise the calculations into named helper methods instead of one long main.

Figure 7.1 — Rectangle capstone flowchart. Each PROCESS box becomes a method; INPUT/OUTPUT stay in main.

2.1 Complete Solution — RectangleProcedural (Fully Commented)

import java.util.Scanner;

public class RectangleProcedural
{
    public static void main(String[] args)
    {
        Scanner sc = new Scanner(System.in);

        // ---------- INPUT (flowchart parallelograms) — main handles user interaction ----------
        System.out.print("Enter length: ");
        double length = Double.parseDouble(sc.nextLine());

        System.out.print("Enter width: ");
        double width = Double.parseDouble(sc.nextLine());

        // ---------- PROCESS — delegate each formula to a dedicated method ----------
        double area = calculateArea(length, width);
        double perimeter = calculatePerimeter(length, width);
        double diagonal = calculateDiagonal(length, width);

        // ---------- OUTPUT ----------
        System.out.println();
        System.out.println("Rectangle " + length + " x " + width + ":");
        System.out.println("  Area      = " + String.format("%.2f", area));
        System.out.println("  Perimeter = " + String.format("%.2f", perimeter));
        System.out.println("  Diagonal  = " + String.format("%.2f", diagonal));
    }

    // Each PROCESS box from the flowchart → one method with a clear name

    static double calculateArea(double length, double width)
    {
        return length * width;
    }

    static double calculatePerimeter(double length, double width)
    {
        return 2 * (length + width);
    }

    static double calculateDiagonal(double length, double width)
    {
        // Pythagoras: diagonal = square root of (length² + width²)
        return Math.sqrt(length * length + width * width);
    }
}
🧠 Mapping Flowchart → Methods
  1. main = coordinator: reads input, calls helper methods in order, prints output. main reads like the flowchart top to bottom.
  2. One method per PROCESS box: calculateArea, calculatePerimeter, calculateDiagonal — each does one calculation and returns a double.
  3. Parameters carry data: length and width flow from Main into each method — like arrows carrying values into sub-flowcharts.
  4. Math.sqrt: built-in Java method for square root. length * length is length²; same for width.
  5. String.format("%.2f", ...): prints the number with 2 decimal places — polish for output, not required for logic.
Why Not Put Scanner Reads Inside the Methods?

You could — but separating input from calculation makes methods reusable. calculateArea(5, 3) works whether the numbers came from the keyboard, a file, or a future object. Keep I/O in main; keep pure calculations in helpers.

3. Adding Validation with Methods + Decisions

Combine Session 05 decisions with methods: validate before calculating.

import java.util.Scanner;

public static void main(String[] args)
{
    Scanner sc = new Scanner(System.in);
    double length = readPositiveDouble(sc, "Enter length: ");
    double width  = readPositiveDouble(sc, "Enter width: ");

    double area = calculateArea(length, width);
    System.out.println("Area = " + String.format("%.2f", area));
}

// Reusable input method — returns a valid positive number
static double readPositiveDouble(Scanner sc, String prompt)
{
    double value = -1;
    while (value <= 0)
    {
        System.out.print(prompt);
        value = Double.parseDouble(sc.nextLine());
        if (value <= 0)
            System.out.println("Must be positive. Try again.");
    }
    return value;    // sends the valid number back to main
}

This pattern — a method that loops until input is valid — is professional-grade structure built entirely from Lesson 01 skills.
