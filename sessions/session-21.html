2. The Relationship Spectrum

All three relationships mean "objects know about each other" — what differs is ownership and lifetime. Think of them as increasingly strong bonds:

Figure 21.1 — The three relationships in UML style: plain arrow = association, hollow diamond = aggregation, filled diamond = composition (diamond sits on the owner).

2.1 Association — "uses-a / works-with"

Definition — Association

An association is a loose relationship where one object simply knows about (holds a reference to) another. Both objects have completely independent lifetimes. Example: a Teacher is assigned to a Classroom; delete either and the other continues to exist.

class Teacher {
    private String name;
    private Classroom assignedRoom;   // ASSOCIATION: reference to a Classroom created ELSEWHERE

    public String getName() { return name; }
    public Classroom getAssignedRoom() { return assignedRoom; }
    public void setAssignedRoom(Classroom assignedRoom) { this.assignedRoom = assignedRoom; }

    public Teacher(String name) { this.name = name; }

    public void teach() {
        if (assignedRoom == null) {
            System.out.println(name + " has no classroom assigned yet.");
            return;
        }
        System.out.println(name + " is teaching in room " + assignedRoom.getRoomNumber() + ".");
    }
}

// In main - the two objects are created independently and then LINKED:
Classroom r12 = new Classroom("R12");
Teacher silva = new Teacher("Mr. Silva");
silva.setAssignedRoom(r12);         // link
silva.teach();
silva.setAssignedRoom(null);        // unlink - BOTH objects still perfectly alive

2.2 Aggregation — "has-a" (shared, detachable parts)

Definition — Aggregation

Aggregation is a whole–part relationship where the whole has a collection of parts, but the parts are created outside and can outlive the whole or move to another whole. Example: a Classroom has Students — but students exist before the room is assigned and survive if the room closes.

import java.util.*;

class Classroom {
    private String roomNumber; // AGGREGATION: the room HOLDS students but did not CREATE them
    private List<Student> students = new ArrayList<>();

    public String getRoomNumber() { return roomNumber; }

    public Classroom(String roomNumber) { this.roomNumber = roomNumber; }

    public void enroll(Student s) {         // parts are handed IN from outside
        students.add(s);
    }

    public void remove(Student s) {         // ...and can leave again, unharmed
        students.remove(s);
    }
}

// In main:
Student amara = new Student("Amara");     // student exists FIRST, independently
Classroom r12 = new Classroom("R12");
r12.enroll(amara);                        // aggregated into the room
Classroom r15 = new Classroom("R15");
r12.remove(amara);
r15.enroll(amara);                        // same student moved - fine!

2.3 Composition — "part-of" (owned, lives and dies with)

Definition — Composition

Composition is the strongest whole–part relationship: the whole creates and owns its parts. Parts cannot be shared with another whole and cannot exist independently — when the whole dies, the parts die with it. Example: a Classroom is composed of Desks; when the classroom is destroyed, its desks are destroyed too.

import java.util.*;

class Desk {
    private int deskNumber;

    public int getDeskNumber() { return deskNumber; }

    public Desk(int number) { this.deskNumber = number; }
}

class Classroom {
    private String roomNumber; // COMPOSITION: the room CREATES its own desks INSIDE itself.
    private List<Desk> desks = new ArrayList<>();

    public String getRoomNumber() { return roomNumber; }

    public Classroom(String roomNumber, int deskCount) {
        this.roomNumber = roomNumber;
        for (int i = 1; i <= deskCount; i++) {
            desks.add(new Desk(i));       // born inside the constructor - never handed in
        }
    }

    // NO public add/remove for desks, and no getter that exposes the list itself.
    public int getDeskCount() { return desks.size(); }
}

// In main:
Classroom r12 = new Classroom("R12", 30);   // 30 desks spring into existence inside
System.out.println(r12.getDeskCount());            // 30
// When r12 becomes unreachable, its desks are unreachable too -
// the Garbage Collector reclaims the WHOLE with all its PARTS.
Figure 21.2 — Complete School system relationships: Teacher uses Classroom; Classroom has Students; Classroom has Desks (composition).
🧠 Beginner's Logic Breakdown
  1. Look WHERE the part is created — that's the giveaway. Association/aggregation: the part is created outside and a reference is passed in. Composition: the part is created inside the whole (usually in its constructor) and never leaves.
  2. Lifetime test: "If the whole is deleted, does the part survive?" Student — yes → aggregation. Desk — no → composition.
  3. Sharing test: "Can two wholes share one part?" One student in two classrooms at once — no (business rule). One desk in two rooms — impossible → composition.
  4. Memory view (Lesson 05 callback): in composition the only references to Desks live inside the Classroom object — when the room becomes garbage, the desks automatically become unreachable garbage too.

Session 21 Summary

  • Association = knows/uses; both independent; link and unlink freely.
  • Aggregation = has-a; parts handed in from outside, can move or outlive the whole.
  • Composition = part-of; parts born inside the whole, never shared, die with it.
  • Giveaways: where is the part created? can it be reached/shared from outside? who controls its life?
  • Teacher uses Classroom; Classroom has Students; Classroom has Desks — the School project applies all three.
