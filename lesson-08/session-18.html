Learning Outcomes – After this session you will be able to:

  • Store mixed derived objects in one base-typed List<LibraryItem> and process them uniformly
  • Override printDetails() with @Override (methods overridable by default) for type-specific output
  • Override toString() — the most-used method in Java (Object)
  • Test an object's actual type with is and cast safely with as
  • Merge the Library's separate lists into one polymorphic catalog

1. The Power Move: One List, Many Types

Because every Book and Dvd is a LibraryItem, they can all live in a List<LibraryItem>:

import java.util.*;

List<LibraryItem> catalog = new ArrayList<>();
catalog.add(new Book("Clean Code", "Robert C. Martin", "978-0132350884", 2008));
catalog.add(new Dvd("Inception", "Christopher Nolan", 148));

// ONE loop handles every item — present and FUTURE:
for (LibraryItem item : catalog)
{
    item.printDetails();      // each Object answers with ITS OWN version — dynamic dispatch
}
Key Point — Why Professionals Love This

Add a new class Magazine extends LibraryItem tomorrow and this loop already works with it — zero changes to existing code. Systems designed around polymorphic collections grow by adding classes, not by editing old ones.

Figure 18.1 — One polymorphic list holds every item type; one loop dispatches to each object's override.

1.1 Overriding toString() — Every Object's Business Card

All classes secretly inherit from Object, which has an overridable method toString(). By default it prints the class name — useless. Override it and your objects describe themselves everywhere:

class Book extends LibraryItem
{
    // ... existing code ...

    @Override
    public String toString()          // Object.toString() is overridable — we override it
    {
        return "Book: " + title + " by " + author;
    }
}

Book b = new Book("Clean Code", "Robert C. Martin", "978-0132350884", 2008);
System.out.println(b);          // prints "Book: Clean Code by Robert C. Martin"
                               // println called toString() for us!

1.2 Peeking Inside the Box: instanceof

Occasionally you genuinely need to know what's inside a base-typed variable:

for (LibraryItem item : catalog) {
    if (item instanceof Dvd) {
        Dvd d = (Dvd) item;
        System.out.println("  DVD runtime: " + d.getDurationMinutes() + " minutes");
    }

    if (item instanceof Book) {
        Book b = (Book) item;
        System.out.println("  isbn: " + b.getIsbn());
    }
}
🧠 Beginner's Logic Breakdown
  1. instanceof asks, cast converts: check the actual type first, then cast. (Modern Java also allows pattern matching: if (item instanceof Dvd d).)
  2. Use sparingly! If your loop is full of instanceof-checks, you're fighting polymorphism instead of using it. Better: move the varying behaviour into an overridable method and let dispatch do the work.

2. Library System — Phase 5 Build

The Client's Request — Phase 5

"The staff hate the separate menus for books and DVDs. One list, one search, one borrow flow please. And listings should show the right details for each item type."

Step 1 — Override printDetails Per Child

// In LibraryItem.java — overridable by default; children may @Override
public void printDetails()
{
    String status = isAvailable ? "Available" : "Borrowed";
    System.out.println(title + " | loan " + loanDays + " days | " + status);
}
// In Book.java — extend the base output with book specifics
@Override
public void printDetails()
{
    super.printDetails();                                  // reuse the common line...
    System.out.println("   Book: by " + author + " (" + yearPublished + ") isbn " + isbn);
}

// In Dvd.java
@Override
public void printDetails()
{
    super.printDetails();
    System.out.println("   DVD: directed by " + director + ", " + durationMinutes + " min");
}

Step 2 — Collapse Two Lists into One

// File: Library.java  (Phase 5)
package librarysystem;

import java.util.*;

class Library {
    // ONE list holds Books AND Dvds — they are all LibraryItems
    private List<LibraryItem> catalog = new ArrayList<>();

    public void add(LibraryItem item) {          // one add replaces addBook/addDvd
        catalog.add(item);
    }

    public LibraryItem find(String title) {      // one find works for every type
        for (LibraryItem item : catalog) {
            if (item.getTitle().equalsIgnoreCase(title)) {
                return item;
            }
        }
        return null;
    }

    public void listAll() {
        System.out.println("--- Catalog (" + catalog.size() + " items) ---");
        for (LibraryItem item : catalog) {
            item.printDetails();     // each item prints ITS OWN details — polymorphism!
        }
    }

    public void listAvailable() {
        for (LibraryItem item : catalog) {
            if (item.isAvailable()) {
                item.printDetails();
            }
        }
    }
}
// In Main — seeding is beautifully uniform now:
Library lib = new Library();
lib.add(new Book("Clean Code", "Robert C. Martin", "978-0132350884", 2008));
lib.add(new Dvd("Inception", "Christopher Nolan", 148));

lib.listAll();
// Clean Code | loan 14 days | Available
//    Book: by Robert C. Martin (2008) isbn 978-0132350884
// Inception | loan 3 days | Available
//    DVD: directed by Christopher Nolan, 148 min
Figure 18.2 — Phase 5 collapses duplicate lists and methods into one polymorphic catalog.
🧠 Beginner's Logic Breakdown
  1. Count what disappeared: two lists → one; two Add methods → one; two Find methods → one; two list-menu branches → one. Polymorphism deleted duplicate code while adding the per-type detail printing the client wanted.
  2. The @Override / method overriding pair at work: item.printDetails() in the loop — the variable is LibraryItem-typed, but each actual object (Book/Dvd) supplies its own override. Same line, two behaviours.
  3. super.printDetails() in every override: children extend rather than duplicate the common status line — one source of truth preserved.
  4. Borrowing needed no change at all: Borrow/Return live in the base and work through the base-typed variable — inherited behaviour and polymorphism cooperating.
