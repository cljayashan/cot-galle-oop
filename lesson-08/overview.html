Lesson 08 of 10 — The Third Pillar of OOP

Polymorphism — One Method, Many Forms

Greek: poly = many, morph = form. The same method call produces different behaviour depending on the actual object at runtime — powered by method overriding with @Override.

⏱ 8 Hours Integrated 📋 Sessions 17 – 18 🏛 Pillar 3 of 4

Learning Outcomes — After this lesson you will be able to:

  • Use method overriding with @Override for runtime polymorphism
  • Store child objects in parent-typed variables and predict which method runs
  • Build a polymorphic List<LibraryItem> catalog (Phase 5)
  • Distinguish overriding from method overloading and method hiding

Key Syntax

import java.util.*;

public void printDetails() { ... }     // parent permits override
@Override
public void printDetails() { ... }    // child replaces

List<LibraryItem> catalog = new ArrayList<>();
catalog.add(new Book(...));
catalog.add(new Dvd(...));
for (LibraryItem item : catalog)
    item.printDetails();   // each Object runs its own version

Lesson 08 Summary

  • @Override + dynamic dispatch = runtime polymorphism via dynamic dispatch.
  • Child objects fit in parent-typed variables because of is-a.
  • One List<BaseType> handles every derived type in a single loop.
  • Library Phase 5: one catalog, one add, per-type printDetails overrides.
