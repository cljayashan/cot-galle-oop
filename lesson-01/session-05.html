1. From Flowchart Diamond to Java if/else

In your Programming Logic module you drew decision diamonds — shapes that ask a yes/no question and send the flow down different paths. In Java, that diamond becomes an if statement. The condition inside the diamond becomes the expression in parentheses; the "Yes" and "No" branches become blocks of code inside curly braces.

Figure 5.1 — One decision diamond = one if/else pair. The condition must evaluate to true or false (a boolean).
Definition — if Statement

An if statement runs a block of code only when its condition is true. Optional else if chains handle additional conditions; a final else catches everything that did not match.

Common Beginner Mistake

Use == (double equals) to compare values. A single = is an assignment ("put this value into the variable"). Writing if (mark = 50) is illegal in Java when used as an if condition — the compiler will stop you.

1.2 Example — Pass or Fail (Fully Commented)

This program reads a student's mark and prints whether they passed. The pass mark is 50 — exactly the kind of decision you drew as a diamond in flowcharts.

import java.util.Scanner;

public class PassFailChecker
{
    public static void main(String[] args)
    {
        Scanner sc = new Scanner(System.in);

        // ---------- INPUT ----------
        System.out.print("Enter your exam mark (0-100): ");
        int mark = Integer.parseInt(sc.nextLine());

        // ---------- DECISION (flowchart diamond) ----------
        // Condition: mark >= 50  →  "Is the mark at least 50?"
        if (mark >= 50)
        {
            // YES branch — the "True" arrow from the diamond
            System.out.println("Congratulations! You PASSED.");
        }
        else
        {
            // NO branch — the "False" arrow from the diamond
            System.out.println("Sorry. You FAILED. Keep studying!");
        }

        // ---------- OUTPUT (extra detail using else if) ----------
        if (mark >= 75)
        {
            System.out.println("Grade band: A (Distinction)");
        }
        else if (mark >= 65)          // only checked if mark < 75
        {
            System.out.println("Grade band: B (Credit)");
        }
        else if (mark >= 50)          // only checked if mark < 65
        {
            System.out.println("Grade band: C (Pass)");
        }
        else                          // mark < 50
        {
            System.out.println("Grade band: F (Fail)");
        }
    }
}
🧠 Beginner's Logic Breakdown — Pass/Fail
  1. The diamond question: mark >= 50 produces a boolean — either true or false. Java only enters the block when the answer is true.
  2. if / else if chain: Java checks conditions top to bottom and runs the first block whose condition is true, then skips the rest. This mirrors a flowchart with multiple diamonds chained together.
  3. Order matters: put the strictest test first (>= 75 before >= 50). If you reversed them, a mark of 80 would match >= 50 first and never reach the A grade block.
  4. Curly braces { }: group multiple statements into one branch. If a branch has only one line, braces are optional — but always use them while learning; they prevent bugs when you add a second line later.

2. Nested if — Decisions Inside Decisions

Sometimes one decision depends on another. In a flowchart you draw one diamond, and the "Yes" path leads to a second diamond. In Java, you place an if inside another if's block — this is called a nested if.

Scenario: A student passes only if their mark is at least 50 and they attended at least 80% of classes.

import java.util.Scanner;

public class NestedIfDemo
{
    public static void main(String[] args)
    {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter exam mark: ");
        int mark = Integer.parseInt(sc.nextLine());

        System.out.print("Enter attendance %: ");
        int attendance = Integer.parseInt(sc.nextLine());

        // OUTER diamond: did they pass the exam?
        if (mark >= 50)
        {
            // INNER diamond: did they attend enough?
            if (attendance >= 80)
            {
                System.out.println("FULL PASS — mark and attendance both OK.");
            }
            else
            {
                System.out.println("MARK PASS but ATTENDANCE FAIL — must repeat.");
            }
        }
        else
        {
            System.out.println("EXAM FAIL — attendance does not matter.");
        }
    }
}

2.1 Combining Conditions with && and ||

Two simple diamonds can often be merged into one using logical operators:

OperatorNameTrue when...Example
&&ANDBoth sides are truemark >= 50 && attendance >= 80
||ORAt least one side is truemark >= 75 || attendance == 100
 
// Same logic as nested if, written as ONE diamond:
if (mark >= 50 && attendance >= 80)
{
    System.out.println("FULL PASS");
}
else if (mark >= 50)
{
    System.out.println("MARK PASS but ATTENDANCE FAIL");
}
else
{
    System.out.println("EXAM FAIL");
}
When to Nest vs Combine

Use && when both conditions must be true at the same level. Use nested if when the inner question only makes sense after the outer one is true (as in our attendance example — we only ask about attendance if the mark already passed).

3. The switch Statement — Perfect for Menus

When you have many fixed choices (1, 2, 3 or 'A', 'B', 'C'), a long chain of if / else if works but gets messy. The switch statement is cleaner: you give it one variable, and Java jumps to the matching case. Every case must end with break; — this tells Java "stop here; do not fall into the next case".

3.1 Example — Simple Menu Program (Fully Commented)

import java.util.Scanner;

public class SimpleMenu
{
    public static void main(String[] args)
    {
        Scanner sc = new Scanner(System.in);

        // Display the menu (OUTPUT)
        System.out.println("=== COT Canteen Menu ===");
        System.out.println("1. Rice & Curry  (Rs. 250)");
        System.out.println("2. Kottu         (Rs. 350)");
        System.out.println("3. Short Eats    (Rs. 120)");
        System.out.println("4. Exit");
        System.out.print("Enter your choice (1-4): ");

        // INPUT — read the user's choice as text, then parse to int
        int choice = Integer.parseInt(sc.nextLine());

        // DECISION — switch on the value of choice
        switch (choice)
        {
            case 1:
                System.out.println("You ordered Rice & Curry. Please pay Rs. 250.");
                break;          // REQUIRED — exits the switch

            case 2:
                System.out.println("You ordered Kottu. Please pay Rs. 350.");
                break;

            case 3:
                System.out.println("You ordered Short Eats. Please pay Rs. 120.");
                break;

            case 4:
                System.out.println("Goodbye!");
                break;

            default:            // catches any value that did not match 1, 2, 3 or 4
                System.out.println("Invalid choice. Please run again and pick 1-4.");
                break;
        }
    }
}
🧠 Beginner's Logic Breakdown — switch
  1. One variable, many paths: switch (choice) compares choice against each case value. It is like a row of diamonds asking "is it 1? is it 2? is it 3?"
  2. break is mandatory: without break;, execution "falls through" into the next case and runs that code too — almost never what you want. Always write break; after each case block.
  3. default = the else branch: catches unexpected input (user typed 9 or -1). Every good menu program needs a default case.
  4. switch vs if/else if: use switch when comparing one variable against several exact values (integers, chars, strings). Use if/else when conditions involve ranges (mark >= 50) or complex logic.
switch with Ranges?

Java switch matches exact values, not ranges. For "mark between 65 and 74" you still need if / else if. (Later Java versions add richer switch forms — we stay with classic switch + break for now.)

Session 05 Summary

  • Flowchart decision diamonds map directly to if, else if and else.
  • Conditions use comparison operators and produce a boolean (true/false).
  • Nested if handles decisions that depend on earlier decisions; && and || combine conditions.
  • switch / case / break / default is ideal for menu programs with fixed numeric or character choices.
  • Always validate input and handle invalid choices with else or default.
