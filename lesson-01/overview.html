Basic Java Programming

Before any Object-Oriented concepts, you learn to write, run and debug real Java programs. This overview condenses the whole lesson; open each session for detailed notes, figures and lab walk-throughs. Every topic maps back to the flowcharts and algorithms you already know.

⏳ 18 Hours Integrated 📚 Sessions 01 – 07 💻 VS Code / JDK

Learning Outcomes – After this lesson you will be able to:

  • Install VS Code with the Extension Pack for Java and create your first Java folder/project
  • Describe the structure of a Java program: package, class, main method, comments and braces
  • Declare variables, read input, convert types and print formatted output
  • Use arithmetic, relational and logical operators in expressions
  • Translate flowchart decisions into if, else if, else and switch statements
  • Translate flowchart loops into while, do-while and for loops
  • Define and call procedural methods with parameters and return values
  • Build a complete procedural program from a flowchart (Rectangle capstone)

1. From Flowcharts to Your First Java Program (Session 01)

You already think in INPUT, PROCESS and OUTPUT boxes. Session 01 connects that mental model to VS Code: open a student folder, create Hello.java, locate Explorer, Editor, Terminal and the PROBLEMS panel, then run your first program. Only VS Code is allowed in this module.

  • Flowchart shapes map to Java: OUTPUT → System.out.println, INPUT → sc.nextLine.
  • An IDE (Integrated Development Environment) combines editor, compiler and debugger in one tool.
  • Tools: VS Code + JDK 17+ (Temurin/Adoptium) + Extension Pack for Java by Microsoft. Open a folder (e.g. MyFirstProgram) and write .java files.
  • Every program starts in main — execution flows top to bottom, just like a flowchart.

2. Anatomy of a Java Program (Session 02)

// Optional package declaration
package myapp;

public class Hello                 // container for related code (file: Hello.java)
{
    public static void main(String[] args)   // entry point
    {
        System.out.println("Hello!");  // every statement ends with ;
    }
}
  • Comments (//) are ignored by the compiler — notes for humans.
  • Semicolons mark the end of each statement; missing one causes '; expected.
  • Braces { } group code into blocks; indentation aids readability.
  • jshell from the VS Code Terminal (jshell): test single lines instantly.

3. Variables, Data Types & Console I/O (Session 03)

Every piece of data lives in a typed variable. Input always arrives as String and must be converted for maths.

  • Read input: sc.nextLine(); convert: Integer.parseInt(...), Double.parseDouble(...).
  • Format output with concatenation: "Hello " + name + " is " + age or String.format.
  • Flowchart mapping: INPUT = Scanner + parse, PROCESS = assignment, OUTPUT = System.out.println.

4. Operators & Formatted Output (Session 04)

  • Arithmetic: +, -, *, /, % — watch integer vs floating-point division.
  • Relational: ==, !=, <, >, <=, >= — compare values, return boolean.
  • Logical: && (AND), || (OR), ! (NOT) — combine conditions.
  • Precedence: parentheses first, then */%, then +/-.
  • Format numbers: String.format("%.2f", value) for two decimal places; printf for column alignment.

5. Decision Structures (Session 05)

Flowchart decision diamonds become Java branching statements.

if (mark >= 50)
    System.out.println("Pass");
else
    System.out.println("Fail");

switch (choice)
{
    case 1: System.out.println("Add"); break;
    case 2: System.out.println("Subtract"); break;
    default: System.out.println("Invalid"); break;
}
  • if / else if / else chains handle multi-level decisions (grade bands, eligibility checks).
  • switch with break suits menu-driven programs with fixed options.
  • Nested if statements handle decisions inside decisions.

6. Loops (Session 06)

Java LoopFlowchart PatternBest For
whilePre-test loop (check first)Repeat until condition changes
do-whilePost-test loop (check after)At least one iteration (menus, validation)
forCounter loopKnown number of repetitions (tables, sums)
  • break exits a loop early; continue skips to the next iteration.
  • Combine loops with decisions from Session 05 for interactive programs.

7. Methods & Capstone (Session 07)

Methods are named, reusable blocks of code — the procedural equivalent of breaking a flowchart into sub-processes. OOP classes come in Lesson 02; here methods live inside the Program class as static helpers.

static double calculateArea(double length, double width)
{
    return length * width;
}

// In Main:
double area = calculateArea(5, 3);   // area = 15
Capstone — RectangleProcedural

Translate the rectangle flowchart into a complete procedural program with separate methods for area, perimeter and diagonal length. This is the bridge to Lesson 02, where the same problem becomes an object.
