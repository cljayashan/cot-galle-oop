Encapsulation & Getters/Setters – The First Pillar of OOP

Hide the data, expose controlled doors. From public/private through classic getter/setter methods to Java's getter/setter convention — then applied to harden the Library System.

⏱ 10 Hours Integrated 📋 Sessions 07 – 09 🔒 Pillar 1 of OOP

Learning Outcomes – After this lesson you will be able to:

  • Define encapsulation and justify data hiding
  • Apply public, private (and know of protected/package-private) access modifiers
  • Write validating setters, simple getters/setters, read-only fields and computed methods
  • Refactor public fields to private fields with getters/setters
  • Enforce business rules (borrow limits) through encapsulated state

1. Access Modifiers (Session 07)

Definition — Encapsulation

Bundling data + methods into one unit while hiding the data from direct outside access. Outsiders use only the public interface. Analogy: an ATM — cash locked inside, interaction only through the keypad.

ModifierAccessUse
publicEverywhereThe class's control panel
privateSame class onlyFields (almost always) + helpers
protectedClass + childrenLesson 06 (inheritance)
package-private (default)Same projectAdvanced

Private members accessed from outside give compiler error a compile-time access error — the compiler is the security guard. Convention: camelCase private fields, camelCase methods; PascalCase only for class names.

2. Java Getters & Setters (Session 08)

class BankAccount {
    private double balance;   // private storage

    public double getBalance() { return balance; }

    public void setBalance(double newBalance) {
        if (newBalance < 0) return;   // validation
        balance = newBalance;
    }
}

// Simple: getTitle() / setTitle(String)
// Read-only: getIsbn() only (no public setter)
// Computed: public double getArea() { return length * width; }
  • Java has no auto-properties — use explicit getters and setters.
  • Ladder: public field (never) → simple getter/setter → validating setter.
  • Never store what you can compute. VS Code: Right-click in editor → Source Action → Generate Getters and Setters (or Ctrl+. → Generate Getters and Setters).

3. Library Phase 2 (Session 09)

private boolean available = true;
public boolean isAvailable() { return available; }
// no public setter — only borrow()/returnBook() change it

private int booksBorrowed;
public int getBooksBorrowed() { return booksBorrowed; }
public static final int MAX_BOOKS = 3;
public boolean canBorrow() { return booksBorrowed < MAX_BOOKS; }

member.borrowBook(book);   // each class enforces its own rule
  • Book refactored: availability sealed inside the class.
  • New Member class enforces the 3-book borrow limit.
  • Refactoring = better insides, unchanged outside behaviour.

Lesson 04 Summary

  • Encapsulation = data hiding + controlled public interface; the compiler enforces it.
  • Fields private; access through getters/setters; validate in setters; compute derived values.
  • No public setter seals state machines inside classes; static final fixes class-wide rules.
  • Library System now physically prevents record corruption and enforces the 3-book limit.
