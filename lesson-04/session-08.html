1. Java Has No Auto-Properties

Session 07’s approach is the correct and standard way in Java: acc.setOwnerName("Ruwan") and acc.getBalance(). Unlike some languages that offer auto-properties (field-like assignment that secretly runs get/set code), Java does not have that feature. You always write explicit methods — and that is a good thing for beginners, because nothing is hidden.

Definition — Getter / Setter

A getter is a public method that returns a private field (getBalance()). A setter is a public method that assigns a new value to a private field after optional validation (setBalance(double amount)). Together they are the Java way to encapsulate data.

Important contrast

Java has no language-level auto-properties. Always write getX/setX (or isX for booleans). VS Code can generate them for you (Right-click → Source Action → Generate Getters and Setters, or Ctrl+. → Generate Getters and Setters).

Figure 8.1 — Getter returns the field; setter validates then stores. Callers never touch balance directly.

1.1 The Full Getter/Setter Pattern

class BankAccount
{
    // 1) The PRIVATE FIELD — stores the actual data
    private double balance;

    // 2) GETTER — read access
    public double getBalance()
    {
        return balance;
    }

    // 3) SETTER — write access with validation
    public void setBalance(double newBalance)
    {
        if (newBalance < 0)
        {
            System.out.println("Balance cannot be negative. Ignored.");
            return;           // reject — the field stays unchanged
        }
        balance = newBalance; // accept and store
    }
}

// ---- Using it ----
BankAccount acc = new BankAccount();
acc.setBalance(5000);               // accepted
acc.setBalance(-99);                // rejected, message printed
System.out.println(acc.getBalance()); // prints 5000
🧠 Beginner’s Logic Breakdown
  1. Two things, one idea: the private field balance is the storage box; getBalance/setBalance are the guarded windows.
  2. The parameter is the incoming value: in setBalance(double newBalance), newBalance is whatever the caller passed.
  3. Naming convention (JavaBeans): field title → getTitle() / setTitle(String title). For boolean, prefer isAvailable() instead of getAvailable().
  4. No magic assignment: you write acc.setBalance(5000), not acc.balance = 5000 from outside.

1.2 Simple Getters/Setters (No Validation)

When a field needs no rules today, still keep it private and generate trivial getters/setters. You can add validation later without changing how callers read the value.

class Book
{
    private String title;
    private String author;
    private String isbn;          // no public setter — read-only from outside
    private boolean available = true;

    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }

    public String getAuthor() { return author; }
    public void setAuthor(String author) { this.author = author; }

    public String getIsbn() { return isbn; }
    // setIsbn stays package/private or used only from constructors/methods inside the class
    void setIsbn(String isbn) { this.isbn = isbn; }

    public boolean isAvailable() { return available; }
    public void setAvailable(boolean available) { this.available = available; }
}
FormSyntaxWhen to Use
Public fieldpublic String title;Never in production code — no protection
Simple getter/settergetTitle() / setTitle(...)Simple storage; rules can be added later
Validating settersetter with if checksWhenever writes need logic/validation
Read-onlypublic getter, no public setterValues set once (ID, ISBN)
VS Code Shortcut

Place the cursor in the class → Right-click → Source Action → Generate Getters and Setters (or press Ctrl+. → Generate Getters and Setters) → select fields. VS Code writes the boilerplate. Standard in professional Java development.

1.3 Computed Methods (Never Store What You Can Calculate)

class Rectangle
{
    private double length;
    private double width;

    public double getLength() { return length; }
    public void setLength(double length) { this.length = length; }
    public double getWidth() { return width; }
    public void setWidth(double width) { this.width = width; }

    // COMPUTED — no stored field; fresh every call
    public double getArea() { return length * width; }
    public double getPerimeter() { return 2 * (length + width); }
    public boolean isSquare() { return length == width; }
}

Rectangle r = new Rectangle();
r.setLength(5);
r.setWidth(3);
System.out.println(r.getArea());   // 15
r.setWidth(10);
System.out.println(r.getArea());   // 50 — always up to date
Key Point

If area were a stored field, changing width could leave a stale value. A computed method cannot be out of date. Rule: never store what you can compute.

2. Employee Example — Every Access Style

// File: Employee.java
public class Employee
{
    private String name;
    private String department;
    private String employeeId;       // read-only from outside
    private double monthlySalary;    // validating setter

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public String getDepartment() { return department; }
    public void setDepartment(String department) { this.department = department; }

    public String getEmployeeId() { return employeeId; }
    public void assignId(String id) { this.employeeId = id; }  // controlled write

    public double getMonthlySalary() { return monthlySalary; }
    public void setMonthlySalary(double monthlySalary)
    {
        if (monthlySalary < 0)
        {
            System.out.println("Salary cannot be negative.");
            return;
        }
        this.monthlySalary = monthlySalary;
    }

    public double getAnnualSalary() { return monthlySalary * 12; }
    public double getEpf() { return monthlySalary * 0.08; }   // 8% EPF

    public void printPaySlip()
    {
        System.out.println("--- Pay Slip: " + employeeId + " ---");
        System.out.println("Name       : " + name + " (" + department + ")");
        System.out.println("Monthly    : " + String.format("%.2f", monthlySalary));
        System.out.println("EPF (8%)   : " + String.format("%.2f", getEpf()));
        System.out.println("Annual     : " + String.format("%.2f", getAnnualSalary()));
    }
}
🧠 Beginner’s Logic Breakdown
  • Pick the right tool: name needs no rules → simple setter. Salary must never be negative → validating setter. Annual salary is derivable → computed method. ID must not change freely → no public setter.
  • Ladder of preference: public field (never) → simple getter/setter → validating setter.

Session Summary

  • Java has no auto-properties — use explicit getX/setX (or isX for booleans).
  • Keep fields private; validate in setters; compute derived values with methods.
  • Read-only from outside = public getter, no public setter.
