1. New Requirements from the Client

The Client’s Request — Phase 2

“We need to register members. Each member has a name, a membership number, and may borrow at most 3 books at a time. We also found a bug risk: staff were editing book data directly and corrupted some records — please make that impossible.”

Translation into our new skills: the “corruption” complaint = we must encapsulate Book. The “at most 3 books” rule = a guarded counter inside Member. Note how naturally requirements map to encapsulation!

Definition — Refactoring

Refactoring means improving the internal structure of code without changing its external behaviour. The menu must work exactly as before — only the insides of Book get safer. Callers switch to get/set methods; the menu behaviour stays the same.

Figure 9.1 — Book state machine: availability toggles only through Borrow() and returnBook(); isAvailable public getter / no public setter seals the transitions.
Figure 9.2 — Member borrow limit: canBorrow is a computed method; when 3/3 books are borrowed, the 4th attempt is refused before Book is even asked.

Step 1 — Refactor Book to Use Getters/Setters

// File: Book.java  (Phase 2 - encapsulated version)

    class Book
    {
        // Simple getters/setters replace public fields.
        // Callers change from book.title = ... to book.setTitle(...). That's refactoring!
        private String title;
        public String getTitle() { return title; }
        public void setTitle(String title) { this.title = title; }
        private String author;
        public String getAuthor() { return author; }
        public void setAuthor(String author) { this.author = author; }

        // ISBN never changes after creation - lock the setter from outside
        private String isbn;
        public String getIsbn() { return isbn; }
        // no public setter — write only inside this class

        // Availability may ONLY change via Borrow/Return - not from outside
            private boolean isAvailable = true;
    public boolean isAvailable() { return isAvailable; }
    private void setAvailable(boolean isAvailable) { this.isAvailable = isAvailable; }

        private int yearPublished;
        public int getYearPublished() { return yearPublished; }
        public void setYearPublished(int yearPublished) { this.yearPublished = yearPublished; }

        // Temporary way to set the locked ISBN (constructors replace this in Phase 3)
        public void setIsbn(String isbn)
        {
            this.isbn = isbn;                      // allowed inside the class
        }

        public boolean borrow()                    // returns success/failure
        {
            if (!isAvailable)
            {
                System.out.println("Sorry, '" + title + "' is already borrowed.");
                return false;                 // state unchanged - still borrowed
            }
            isAvailable = false;              // legal: we are inside the class
            System.out.println("You have borrowed '" + title + "'.");
            return true;
        }

        public void returnBook()
        {
            if (isAvailable)
            {
                System.out.println("'" + title + "' was not borrowed.");
                return;
            }
            isAvailable = true;
            System.out.println("'" + title + "' returned. Thank you!");
        }

        public void printDetails()
        {
            String status = isAvailable ? "Available" : "Borrowed";
            System.out.println(title + " by " + author + " (" + yearPublished + ") | ISBN: " + isbn + " | " + status);
        }
    }
🧠 Beginner’s Logic Breakdown — Book
  1. Why the program still compiles: callers switch from public fields to b1.setTitle("...") / b1.getTitle(). Only lines that set ISBN or isAvailable directly will now error — exactly the dangerous lines we want to catch.
  2. isAvailable public getter / no public setter is the heart of Phase 2: everyone may check availability, but only borrow() and returnBook() may change it.
  3. borrow() now returns boolean because the Member class needs to know whether the borrow actually happened before counting it.

Step 2 — The Member Class (New)

// File: Member.java

    class Member
    {
        private static final int MAX_BOOKS = 3;           // static final = fixed forever, class-wide rule

        private String name;
        public String getName() { return name; }
        public void setName(String name) { this.name = name; }
        private String membershipNumber;
        public String getMembershipNumber() { return membershipNumber; }
        // no public setter — write only inside this class

        // Encapsulated counter: readable by all, changeable only by borrowBook/returnBook
            private int booksBorrowed = 0;
    public int getBooksBorrowed() { return booksBorrowed; }
    private void setBooksBorrowed(int booksBorrowed) { this.booksBorrowed = booksBorrowed; }

        // Computed method - always accurate, derived from the counter
        public boolean canBorrow() { return booksBorrowed < MAX_BOOKS; }

        public void setMembershipNumber(String number)
        {
            this.membershipNumber = number;        // private set allowed inside the class
        }

        public void borrowBook(Book book)
        {
            if (!canBorrow())
            {
                System.out.println(name + " already has " + booksBorrowed + " books - limit is " + MAX_BOOKS + ".");
                return;
            }

            boolean success = book.borrow();     // ask the Book; it enforces ITS own rule
            if (success)
            {
                booksBorrowed++;              // ++ adds 1; only counted if borrow worked
                System.out.println(name + " now has " + booksBorrowed + " book(s).");
            }
        }

        public void returnBook(Book book)
        {
            book.returnBook();
            if (booksBorrowed > 0)
            {
                booksBorrowed--;              // -- subtracts 1
            }
        }

        public void printCard()
        {
            System.out.println("[" + membershipNumber + "] " + name + " - borrowed: " + booksBorrowed + "/" + MAX_BOOKS);
        }
    }
🧠 Beginner’s Logic Breakdown — Member
  1. Two objects cooperating: member.borrowBook(book) passes a Book object as a parameter. Member asks Book to borrow itself; each class enforces its own rule.
  2. const: MAX_BOOKS is a rule, not data — it cannot change while the program runs.
  3. Trust chain: borrowBook only increments when book.borrow() reported true. Correct bookkeeping falls out when each class guards its own state.

2. Menu Updates for Phase 2

Extend your Phase 1 Main.java menu with member registration and member-aware borrowing. Below is a reference pattern for the new options:

import java.util.ArrayList;
import java.util.List;

import java.util.Scanner;

// File: Main.java  (excerpt - menu additions for Phase 2)

    public class Main
    {
        static List<Book> books = new ArrayList<>();
        static List<Member> members = new ArrayList<>();   // NEW list for members

        public static void main(String[] args)
        {
        Scanner scanner = new Scanner(System.in);
            // ... seed books from Phase 1 ...

            boolean running = true;
            while (running)
            {
                System.out.println("\n=== Library System - Phase 2 ===");
                System.out.println("1. Add book    2. List books    3. Search book");
                System.out.println("4. Borrow book 5. Return book   6. Show available");
                System.out.println("7. Register member  8. Show member cards");   // NEW
                System.out.println("0. Exit");
                System.out.print("Choice: ");
                String choice = scanner.nextLine();

                switch (choice)
                {
                    case "4":
                        borrowWithMember();    // CHANGED: ask which member first
                        break;
                    case "7":
                        registerMember();      // NEW
                        break;
                    case "8":
                        showMemberCards();     // NEW
                        break;
                    // ... other cases unchanged ...
                }
            }
        }

        static void registerMember()
        {
            Member m = new Member();
            System.out.print("Name: ");
            m.setName(scanner.nextLine());
            System.out.print("Membership number: ");
            m.setMembershipNumber(scanner.nextLine());
            members.add(m);
            System.out.println("Member registered.");
        }

        static void showMemberCards()
        {
            for (Member m : members)
                m.printCard();
        }

        static void borrowWithMember()
        {
            System.out.print("Member number: ");
            String num = scanner.nextLine();
            Member found = null;
            for (Member m : members) {
                if (m.getMembershipNumber().equals(num)) { found = m; break; }
            }
            if (found == null) { System.out.println("Member not found."); return; }

            System.out.print("Book ISBN: ");
            String isbn = scanner.nextLine();
            Book book = null;
            for (Book b : books) {
                if (b.getIsbn().equals(isbn)) { book = b; break; }
            }
            if (book == null) { System.out.println("Book not found."); return; }

            found.borrowBook(book);            // Member + Book cooperate
        }
    }

Session 09 Summary — Library Phase 2 Complete

  • Refactoring = safer insides, same outside behaviour; properties keep field-like syntax.
  • private set sealed the Book’s availability state machine inside the class.
  • Member enforces the 3-book limit with a guarded counter and a computed canBorrow.
  • Objects passed as parameters let classes cooperate while each guards its own state.
  • The compiler now physically prevents the data corruption the client complained about.
