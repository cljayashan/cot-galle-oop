Constructors & Method Overloading

Objects born complete and valid in one line, plus one method name serving many input shapes. Applied in Library System Phase 3 with a new Library class.

⏱ 10 Hours Integrated 📋 Sessions 10 – 12 📚 Library Project Phase 3

Learning Outcomes – After this lesson you will be able to:

  • Write default, parameterized and chained constructors
  • Use this for field/parameter clashes and constructor chaining
  • Define valid overloads and predict compiler overload selection
  • Refactor object creation to constructors across a project

1. Constructors (Session 10)

Definition — Constructor

A special method with the class's own name and no return type that runs automatically, exactly once, when new creates the object. Its job: a valid starting state.

class Book
{
    private String isbn;
    public String getIsbn() { return isbn; }
    // no public setter — write only inside this class

    public Book(String title, String author, String isbn)   // parameterized constructor
    {
        this.title = title; this.author = author;
        this.isbn = isbn;               // constructors may set private-set properties
    }
}

Book b = new Book("Clean Code", "Robert C. Martin", "978-0132350884");  // one line, complete
// new Book()  -> compiler error: your own constructor removed the free empty one
  • this.name = name; — field vs parameter clash resolution.
  • public Student(String name) { this(name, 18); } — chaining, one place for logic.
  • Trap: adding void makes it an ordinary method, not a constructor.

2. Method Overloading & the this Keyword (Session 11)

Definition — Overloading

Several methods with the same name but different parameter lists (count, types or order). The compiler picks the match from the arguments — compile-time polymorphism. Return type alone cannot distinguish overloads.

public int    Add(int a, int b)           // ok
public int    Add(int a, int b, int c)    // ok – different count
public double add(double a, double b)     // ok – different types
// public double add(int a, int b)        // ERROR – only return type differs

public Student(String name) {
        this(name, 18);
    }   // this(...) must be first statement — chains constructors
  • Overload identical-meaning operations (Add, Find); use separate names for different meanings (findByIsbn).
  • this refers to the current object — resolves field/parameter name clashes and enables constructor chaining.

3. Library Phase 3 (Session 12)

import java.util.ArrayList;
import java.util.List;

class Library
{
    private List<Book> catalog = new ArrayList<>();

    public void addBook(Book book) { catalog.add(book); }

    public Book find(String title) { ... }              // overload by parameter count/types
    public Book find(String author, int year) { ... }
    public Book findByIsbn(String isbn) { ... }         // separate name when meaning differs
}
  • Book: full constructor + short overload chaining; Set methods deleted.
  • New Library class owns the private catalog with overloaded search.
  • Patterns: return inside foreach exits on first match; ToLower() for case-insensitive compare; null when not found.

Lesson 05 Summary

  • Constructors guarantee complete, valid objects; chaining removes duplication.
  • Overloads differ by parameter list only; compiler routes calls at compile time.
  • this resolves name clashes and chains constructors to a single logic point.
  • Library System: one-line creation, dedicated Library class, flexible search.
