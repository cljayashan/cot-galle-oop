1. Method Overloading — One Name, Many Versions

Definition — Method Overloading

Method overloading means defining several methods in the same class with the same name but different parameter lists (different number, types, or order of parameters). The compiler selects the correct version by matching the arguments at the call site. This is compile-time polymorphism.

You have already used overloading: System.out.println is overloaded for String, int, double, and more — each is a different overload of one method name.

class Calculator
{
    // Overload 1: two ints
    public int add(int a, int b)
    {
        return a + b;
    }

    // Overload 2: three ints — different COUNT
    public int add(int a, int b, int c)
    {
        return a + b + c;
    }

    // Overload 3: two doubles — different TYPES
    public double add(double a, double b)
    {
        return a + b;
    }

    // Overload 4: String + int — different types and meaning
    public String add(String text, int number)
    {
        return text + number;    // "Room" + 5 → "Room5"
    }

    // ILLEGAL — only return type differs from Overload 1:
    // public double add(int a, int b) { return a + b; }
    // Error: already defines 'Add' with the same parameter types
}

Calculator calc = new Calculator();
System.out.println(calc.add(2, 3));          // → Overload 1 → 5
System.out.println(calc.add(2, 3, 4));       // → Overload 2 → 9
System.out.println(calc.add(2.5, 3.5));      // → Overload 3 → 6.0
System.out.println(calc.add("Room", 5));     // → Overload 4 → Room5

1.1 Overloading Rules

RuleValid?Example
Different parameter count✓ Yesadd(int, int) vs Add(int, int, int)
Different parameter types✓ Yesadd(int, int) vs add(double, double)
Different parameter order✓ Yesprint(int, String) vs print(String, int)
Different return type only✗ Noint Get() vs double Get() — compiler cannot choose from the call alone
Only parameter names differ✗ NoNot a distinct overload in Java
Figure 11.1 — The compiler routes each call to exactly one overload by comparing argument types and count against every candidate signature.
🧠 Beginner's Logic Breakdown
  1. Receptionist analogy: four staff members all named "Add" sit at different desks. The receptionist (compiler) reads what the visitor carries — two ints go to desk 1, three ints to desk 2. Routing is decided when the code compiles, not when it runs.
  2. Why return type fails: in calc.add(2, 3) nothing tells the compiler whether you want an int or double back. Only the parameter list can distinguish overloads.
  3. Overload when meanings match: Search, Print, Add — same operation, different inputs. Use separate names when operations differ in purpose.

2. Constructor Overloading & Chaining with this

Multiple constructors in one class follow the same overloading rules as methods. The class name is the method name; Java picks the constructor whose parameter list matches the new arguments.

class Book
{
    private String title;
    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }
    private String author;
    public String getAuthor() { return author; }
    public void setAuthor(String author) { this.author = author; }
    private String isbn;
    public String getIsbn() { return isbn; }
    // no public setter — write only inside this class
    private int yearPublished;
    public int getYearPublished() { return yearPublished; }
    public void setYearPublished(int yearPublished) { this.yearPublished = yearPublished; }
    private boolean isAvailable;
    public boolean isAvailable() { return isAvailable; }
    // no public setter — write only inside this class

    // Primary constructor — all required data
    public Book(String title, String author, String isbn, int yearPublished)
    {
        this.title = title;
        this.author = author;
        this.isbn = isbn;
        this.yearPublished = yearPublished;
        isAvailable = true;
    }

    // Overloaded constructor — year unknown; chains to primary with year = 0
    public Book(String title, String author, String isbn) {
        this(title, author, isbn, 0);
        // Body runs AFTER the chained constructor finishes.
        // Year 0 conventionally means "unknown publication year".
    }
}

Book b1 = new Book("Clean Code", "Robert C. Martin", "978-0132350884", 2008);
Book b2 = new Book("Head First Java", "Andrew Stellman", "978-1491976708");  // overload 2

2.2 this — Two Uses Recap

UseSyntaxPurpose
Name resolutionthis.name = name;Distinguish field from parameter with the same identifier
Constructor chainingpublic Student(String n) { this(n, 18); }One constructor calls another; avoids duplicate assignment logic
 
class Student
{
    private String name;
    private int age;

    public Student(String name, int age)
    {
        this.name = name;     // Use 1: name resolution
        this.age = age;
    }

    public Student(String name)
    {
        this(name, 18);   // Use 2: chaining — default age 18
    }

    public Student()
    {
        this("Unnamed", 18);   // chains through the one-param constructor
    }
}
Chaining Rule

this(...) must be the first statement in the constructor body and must call another constructor in the same class. The chained constructor runs completely before any remaining statements in the current constructor.

Session 11 Summary

  • Overloading = same name, different parameter lists; compiler resolves at compile time.
  • Return type alone can never distinguish overloads — the call site carries no return-type information.
  • Constructors overload exactly like methods; this(...) chains constructors and eliminates duplication.
  • this.field resolves name clashes; this(...) delegates construction to another constructor.
  • Overload when operations are conceptually identical; use distinct names when meanings differ.
