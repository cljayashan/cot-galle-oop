Memory & Object Lifecycle — Stack, Heap and the Garbage Collector

Where does an object actually live when you write new Book(...)? Why can two variables change the same data? And who cleans up objects nobody uses? This lesson looks under the hood of the JVM — and several confusing bugs suddenly make sense.

⏱ 4 Hours Integrated 📋 Session 13 🔍 Explains reference bugs

Learning Outcomes — After this lesson you will be able to:

  • Describe the stack and the heap and what is stored in each
  • Distinguish value types from reference types and predict copy behaviour
  • Trace what happens in memory when an object is created and passed around
  • Explain in simple terms how the JVM Garbage Collector works
  • Explain null and the NullPointerException in memory terms

1. Stack vs Heap

  • Stack: per-method tray pile — local variables, parameters; destroyed instantly when a method returns.
  • Heap: shared warehouse — every object created with new; cleaned by the Garbage Collector.
  • Value types / primitives (int, double, boolean, char) hold data directly. Reference types (class objects, String, arrays, List) hold an address pointing to the heap.
int a = 10;  int b = a;   b = 99;        // a is still 10 — independent copies
Book x = new Book(...);  Book y = x;     // ONE Object, two remotes
y.setTitle("HACKED");                      // x.getTitle() is also "HACKED"!

Passing an object to a method passes a copy of the address — the method can change the caller's object. Reassigning the parameter (p = new Person()) affects nothing outside.

2. Object Lifecycle & the Garbage Collector

  1. Birth: new allocates heap space and runs the constructor.
  2. Life: reachable through at least one reference.
  3. Abandonment: last reference gone — object is unreachable but still occupies memory.
  4. Collection: GC marks reachable objects, sweeps the rest, compacts survivors.

null means the reference holds no address. Using it throws NullPointerException.

Lesson 06 Summary

  • Stack = fast, per-method; heap = where new objects live.
  • Value types copy data; reference types copy the address — two remotes, one TV.
  • The GC reclaims unreachable objects automatically — no manual delete in Java.
  • null = points at nothing; always guard before use.
